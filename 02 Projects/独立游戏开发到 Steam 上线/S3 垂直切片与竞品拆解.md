# S3 · 垂直切片与竞品拆解（2 周）

> 目标：用 2 周做出**"最终品质的 5 分钟"**，而不是"半成品的 5 小时"。
> 垂直切片（Vertical Slice）是一条**穿过所有层级的窄切面**：最终的美术风格、最终的手感、最终的音乐、最终的 UI 观感，只做 5 分钟内容。
> 它的作用是回答一个残酷的问题：**"如果整个游戏都是这个品质，我做得完吗？玩家想买吗？"**

> 编号约定：D1 = 本阶段第 1 天，不是全局第 1 天（本阶段为 2 周，用 W5-D1 ~ W6-D7 标记）。

## 实战需求

**需求 A：可玩切片（5 分钟完整闭环）**

必须包含完整链路，不许有"待补"：

```text
标题画面 → 开始 → 教学（无文字或极少文字）→ 核心玩法 3 分钟 → 一个小高潮/Boss → 死亡或通关
        → 结算画面 → 重开按钮 → 再次进入
```

品质要求：**除了内容量少，任何一处都不像"临时方案"**（不许出现灰色方块、默认字体、默认音效、Debug 文字）。

**需求 B：可对外发布的素材包（营销资产）**

- 5 张商店页截图（**≥1920×1080**，含 UI、含玩法、含结果，不要全是风景）。
- 1 个 30–45 秒无声也能看懂的 GIF / 短视频（前 5 秒必须出现核心动词与反馈）。
- 1 段 100 字的商店页短描述（后来直接用于 [[S7 Steam 上架全流程]]）。

**需求 C：5 份陌生人试玩记录**

按下面的《试玩协议》执行，记录卡直接复制本节的 6 个观察项。

**需求 D：竞品拆解表（3 款）**

不是"我喜欢它哪里"，而是**量化拆解**，找出自己的差异化缝隙。

## 知识点

### 1. 垂直切片 vs 水平切片

| | 水平切片（Horizontal） | **垂直切片（Vertical）** |
| --- | --- | --- |
| 做法 | 每个系统都做一点，美术音乐全用占位 | 只做 5 分钟，但每一层都达到最终品质 |
| 结果 | 3 个月后仍然"什么都有一点，什么都不好玩" | 2 周后就能判断玩法与品质能否成立 |
| 风险 | 全部推翻重做，且信心耗尽 | 提前暴露真实成本（这才是它的价值） |
| 用什么 | ❌ 第一款游戏不要用 | ✅ 本阶段的目标 |

> [!important] 垂直切片的真正用途
> 它的产出物同时是：① 玩法可行性的证据 ② 试玩测试的材料 ③ **商店页与预告片的素材** ④ 后续量产的"品质标准"。
> 一份切片被四种用途复用，这是它性价比高的原因。

### 2. 为什么必须在第 5–6 周做（而不是最后）

- **暴露真实成本**：你会在第 5 周就发现"一个敌人要 2 天"，从而立刻砍内容，而不是在第 20 周崩溃。
- **尽早拿到外部反馈**：此时改方向成本最低。
- **尽早开始攒愿望单**：商店页上线是营销的起点（见 [[S8 营销发售与复盘]]），而商店页需要截图与描述。

### 3. 竞品拆解表（差异化从这里长出来）

选 **3 款**：1 款爆款、1 款中腰部（评价 500–5000 条）、1 款卖得不好的同类。第三款最有价值——**看它做错了什么**。

| 维度 | 竞品 A | 竞品 B | 竞品 C | 我的切片 |
| --- | --- | --- | --- | --- |
| 核心动词 | | | | |
| 单局时长 | | | | |
| 系统数量（数一数 UI 图标） | | | | |
| 内容量（关卡/敌人/Boss 数） | | | | |
| 定价 / 折扣历史 | | | | |
| 评价数 / 好评率 | | | | |
| 发售日（判断市场是否已饱和） | | | | |
| 它做对了什么 | | | | |
| **它缺什么 / 玩家差评在骂什么** | | | | **← 我的机会** |
| 它的商店页第一屏说了什么 | | | | |

> [!tip] 差评是最便宜的策划案
> 把竞品的前 50 条**差评**读完，你会拿到一本"新手会犯的错误清单"，以及一个现成的差异化方向。

### 4. 试玩协议（这一步做错就白做）

**规则（必须遵守）：**

1. **不解释、不提示、不引导、不道歉**。对方问怎么操作，回答"你随便试试看"。
2. 你只做三件事：**看屏幕、记时间、记表情**。
3. 记录卡（每人一份）：
   - 第几秒他开始动？
   - 第几秒他第一次成功（第一次击杀/第一次得分）？
   - 第几秒他卡住？卡在哪个具体画面？
   - 他有没有自言自语？原话记下来。
   - 他玩完后问的第一个问题是什么？
   - **他愿不愿意再玩一局？**（最重要的一栏）
4. **5 个人足够**发现大部分严重可用性问题（这是通用的可用性测试经验值）。不要等到有 50 个人才测试。

**什么时候提示他？** 当且仅当他 90 秒内完全没动作。记住：你想提示的那句话，就是你该写进教程的内容。

### 5. 迭代循环（2 周至少转 3 圈）

```text
出构建 → 找人玩 15 分钟 → 记录卡 → 只挑 Top 3 问题 → 改 → 再出构建
```

**铁律**：每轮只改 3 个问题。改 10 个问题等于没改，因为你无法判断哪个改动的效果。

### 6. 切片的"完成"定义（退出条件）

切片结束不是"做得差不多了"，而是以下全满足：

- [ ] 陌生人 90 秒内自己开始玩，不需要你说话
- [ ] 陌生人 3 分钟内至少成功一次
- [ ] ≥ 3/5 的人主动说"再来一局"或主动重开
- [ ] 5 张截图（**≥1920×1080**，第 1 张是核心动词、**无占位素材与 Debug 文字**）与 **30–45 秒** GIF 可直接用于商店页
- [ ] 你明确知道**剩下的 8 周要"填"哪些内容**（内容清单具体到数量）

> 如果 2 周后达不到以上条件：**改玩法或砍范围，而不是延长切片时间**。切片的长度是固定的，这是它最有用的一点。

## 验收标准

- [ ] 切片可导出为 exe，在别人的电脑上双击可运行
- [ ] 全链路（标题→玩法→结算→重开）无卡死、无 Debug 文字、无占位素材
- [ ] 5 份试玩记录卡填写完整，含"第几秒卡住"的具体数据
- [ ] ≥ 3/5 试玩者主动想再来一局
- [ ] 5 张截图 + 30 秒 GIF + 100 字描述三件套完成
- [ ] 剩余内容清单落到具体数字（例：**3–4 个敌人、1 个 Boss、6–8 个房间**——先按 [[附录 C 范围与功能裁剪决策卡]] 的工时算式倒推，超出预算的数字一律不写）
- [ ] 经过一次 [[附录 C 范围与功能裁剪决策卡]] 的正式裁剪，Cut 列表已更新

## 常见坑

1. **切片做成了"小游戏"**：切片的内容量少，但**品质必须等于成品**；做了个占位美术的切片等于没做。
2. **只顾做美术，忘了走通闭环**：没有"结算→重开"的切片，测不出玩家是否愿意再来一局。
3. **只找熟人试玩**：熟人会夸你。优先找不同性别、不同游戏经验的人，至少一半是"不怎么玩游戏的人"。
4. **试玩时忍不住解释**：一旦解释，数据全废，你会误以为教程没问题。
5. **改 10 个问题**：无法归因，等于掷骰子。
6. **切片品质超标导致量产不可能**：如果你 2 周只能做 5 分钟这个品质，那 8 周只能做到 20 分钟——**这时候要砍范围，不是延工期**。
7. **竞品只拆爆款**：爆款的成功往往不可复制（运气 + 时机 + 团队积累）。拆"中腰部"和"失败品"学到的东西更多。
8. **切片完成后直接开始"加内容"而不再测试**：从 W7 开始，每 2 周仍要有一次外部试玩。

## AI 协作提示词

**让 AI 设计试玩记录卡与问题归因（W6 用）：**
```text
我是独立开发者，刚做完 5 分钟的垂直切片，准备找 5 个陌生人试玩。
请给我一份纸质记录卡（可直接打印填写），
要求：包含 6 个可量化的观察项（含时间戳字段）、3 个开放式问题、1 个"是否愿意再来一局"的问题。
不要问"你觉得好玩吗"这类无效问题，并说明每个问题能诊断什么。
```

**让 AI 只改 Top3（防过度修改）：**
```text
下面是 5 份试玩记录（贴内容）。
请先归纳出现频率最高的问题，然后**只挑 3 个**建议我优先修改，
并说明为什么另外那些先不改。每个建议给出最小改动方案（预计 1–4 小时可完成），不要重写我的设计。
```

**让 AI 审查商店页截图是否有效：**
```text
我要把这几张截图放到 Steam 商店页（描述如下：贴截图内容描述）。
请以"玩家只扫一眼"的视角，指出：哪张应该放第一张？哪些截图没有传达玩法？
3 个会让玩家划走的点。不要给完整文案。
```

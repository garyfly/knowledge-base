# S1 · 游戏系统内核（2 周 / W2–W3）

> 编号约定：D1 = 本阶段第 1 天，不是全局第 1 天。

> 目标：做出一个「**能打、能死、能重开**」的可玩原型，并把游戏编程的 8 个内核系统各过一遍。
> 每个系统只要「够用的最脏版本」——原型期的目标是让循环跑起来，不是让代码好看。

> [!important] 原型允许脏代码
> 这一阶段写出来的 `match` 状态机、硬编码常量、到处 `connect` 的信号，都是**故意的**。
> 架构整理、解耦、写测试留到 [[S5 内容量产与打磨]] 与 [[S6 系统层本地化与打包]]。
> 新手最大的时间黑洞不是「不会写」，而是「在还不知道游戏长什么样的时候就开始重构」。

8 个内核系统（本阶段的全部考点）：

```text
① 输入处理        ② 游戏状态机        ③ 实体生命周期与对象池   ④ 碰撞层与掩码
⑤ 相机跟随与前瞻   ⑥ UI 与场景切换     ⑦ 数据驱动配置           ⑧ 时间控制
```

## 实战需求

**做一个「能打、能死、能重开」的可玩原型（不是完整游戏，是能玩 5 分钟的骨架）。**

| 项 | 要求 |
| --- | --- |
| 状态流转 | 菜单 → 游戏中 → 暂停 → 死亡 → 结算，任意状态都能回到菜单或重开，无残留 |
| 战斗 | 玩家可移动 + 攻击（近战判定或射击，二选一）；攻击要有前摇/冷却之一 |
| 敌人 | 至少 2 种敌人（会追、会撞、会死），其中一种造成伤害 |
| 生命 | 玩家有 HP，受击有无敌帧；HP 归零进死亡流程 → 结算 |
| 重开 | 结算按 R 重开，连续三次重开后 HP、敌人、计时、分数全部回到初值 |
| 碰撞 | 玩家不穿墙，攻击只命中敌人不命中自己；场景里至少有「墙」和「敌人」两类碰撞体 |
| 相机 | `Camera2D` 跟随玩家，有边界限制与平滑，攻击/受击时有屏幕震动 |
| UI | 血条 + 分数用 `Control` 实现；暂停菜单在暂停时**仍可点击** |
| 数值 | 敌人 HP/速度/伤害来自 `.tres` 或 `.json`，改数值不用改 `.gd` |
| 性能 | 固定测试场景下连续生成 200 发子弹仍稳定 **60 FPS**（用对象池），并记录 1% Low 帧时间 |

> [!warning] 本阶段不做的（做了就是浪费时间）
> 存档、设置菜单、键位重绑、手柄、多语言（全部是 [[S6 系统层本地化与打包]] 的活）；关卡编辑工具；联机；成就；完整的关卡内容——内容是 [[S5 内容量产与打磨]] 的事。

## 知识点与对照

| 引擎概念 | 你的 TS/Node 直觉 | 在 Godot 里真实是什么 | 要能回答 |
| --- | --- | --- | --- |
| Input Map | 手写 `keydown` 监听 | 项目设置里把物理键映射成**动作名**（`move_left`、`attack`），代码只读动作 | 为什么代码里不该出现 `KEY_SPACE`？ |
| `_input` vs `_unhandled_input` | 冒泡 / `preventDefault` | `_input` 最先收到所有输入；`_unhandled_input` 在 GUI 处理完没人消费时才收到 | 玩家攻击键在 UI 打开时不该触发，该用哪个？ |
| 输入缓冲 | 事件队列 + 时间戳 | 记录「按键时刻」而不是「当前是否按下」，在 100–150ms（约 6–9 帧）窗口内仍然承认它 | 连招为什么不能只靠 `is_action_just_pressed`？ |
| 状态机 GameState | 一个 `enum` + `switch` | 引擎不提供状态机，就是你手写的 `enum` + `match`，放在 Autoload 单例里 | 为什么状态不该存成多个 bool（`is_paused` + `is_dead`）？ |
| 实体生命周期 | `new` / GC | 节点要 `instantiate()` + `add_child()` 才活；`queue_free()` 是**延迟**释放 | 释放后同一帧还能访问它吗？ |
| 对象池 | 复用对象避免 GC 抖动 | 预先造好一批节点，用 `visible`/`set_process` 开关复用，而不是反复 new/free | 池里复用的子弹为什么会带着上一发的速度？ |
| 碰撞层 layer | CSS `z-index` 是渲染，无关 | `collision_layer` = 我属于哪些层；`collision_mask` = 我**主动检测**哪些层 | A 要撞到 B，要改 A 的哪一项？ |
| Camera2D | `position: fixed` 的容器 | 一个节点，跟随目标 + `limit_*` 边界 + `position_smoothing_*` + `offset` 做震动 | 震动为什么改 `offset` 而不是改 `position`？ |
| `Control` / `CanvasLayer` | Flexbox 布局 | `Control` 是 UI 节点（锚点定位），`CanvasLayer` 让 UI 不跟着相机移动 | 为什么 HUD 必须放进 `CanvasLayer`？ |
| 场景切换 | 路由跳转 | `get_tree().change_scene_to_file()` 在帧末执行，旧节点会被释放 | 为什么切场景后按钮的旧引用全失效了？ |
| Resource / JSON | 配置文件 | `Resource` 可在编辑器里可视化编辑并存成 `.tres`；JSON 更适合外部调参 | 为什么数值不该硬编码在 `_ready` 里？ |
| `Engine.time_scale` | 播放速度倍率 | 缩放**所有** `delta`，暂停用 `get_tree().paused` + `process_mode` | 慢动作后忘了恢复会留下什么 bug？ |

## 任务清单（按天）

- [ ] D2 输入分流：用打印验证 `_input` → GUI → `_unhandled_input` 的先后顺序；把「打开菜单时按攻击键不触发攻击」做对；给攻击加 150ms 输入缓冲并手测
- [ ] D3 状态机 v0：写 `GameState` Autoload（`enum` + `match`），实现菜单/游戏中/暂停/死亡/结算切换，ESC 暂停并让游戏停下来
- [ ] D4 碰撞体系：在「项目设置 → 层名称 → 2D 物理」给 Player / Enemy / Wall / PlayerAttack / EnemyAttack 命名；用 `CharacterBody2D` + `move_and_slide()` 做到不穿墙
- [ ] D5 玩家：移动 + 攻击（近战用 `Area2D` 或射线，射击用实例化子弹），受击扣血 + 无敌帧闪烁
- [ ] D6 敌人：写两种敌人（追人撞人 / 站桩射击），会对自己造成伤害、HP 归零后消失；这一版允许数值硬编码
- [ ] D7 第一周复盘：导出一次 exe，找一个人玩 5 分钟，记录他卡在哪；对照「要能回答」那一列自查

### 第 2 周：能重开、能调（D8–D14）

- [ ] D8 相机：`Camera2D` 跟随玩家，加 `limit_*` 边界与 `position_smoothing_*`，按朝向/速度做前瞻；写一个 `shake(strength)` 函数（改 `offset`）
- [ ] D9 UI：`CanvasLayer` + `Control` 做血条与分数；做暂停菜单；用 `process_mode` 让 UI 在 `paused` 时仍能响应
- [ ] D10 场景与解耦：所有场景切换走一个统一入口；信号连接前用 `is_connected` 判断，或改用场景内连接；理解 `change_scene_to_file` 的执行时机
- [ ] D11 数据驱动：把敌人 HP/速度/伤害抽成 `class_name EnemyStats extends Resource`（`.tres`）或 JSON；做到「只改数据文件就把敌人数值调一遍」
- [ ] D12 对象池：把子弹/伤害数字改成预分配池，回收时重置速度、HP、可见性、`monitoring`；对比池化前后生成 200 个的帧率
- [ ] D13 时间控制：命中瞬间 `Engine.time_scale = 0.3`（持续约 0.15 秒）再回弹；死亡后慢动作进结算；确认慢动作不影响暂停菜单的动画
- [ ] D14 验收与交付：走完整流程三次无残留；导出 exe 给陌生人玩；写复盘

## 验收标准

- [ ] 从菜单开始 → 玩 → 死亡 → 结算 → 重开，连续 3 次，HP/敌人/计时/分数**全部**回到初值
- [ ] 暂停时角色不动，暂停菜单能通过键盘/鼠标操作，恢复后一切正常
- [ ] 慢动作结束后 `Engine.time_scale` 回到 1（专门验证一次「暂停再恢复」后没有 0.3 倍速残留）
- [ ] 玩家不穿墙；把敌人的 collision mask 故意改错后，你能说出「为什么现在打不中了」
- [ ] 改一个 `.tres` 或 `.json` 里的数值，重启游戏后行为变化，全程没改 `.gd`
- [ ] 固定测试场景下连续生成 200 发子弹仍稳定 60 FPS，并记录池化前后的 1% Low 帧时间对比数字
- [ ] 能不看代码画出状态机迁移图，以及一张「输入 → 状态 → 实体 → UI」的数据流图
- [ ] 导出的 exe 在别人的电脑上能跑通完整流程，且对方没听你解释就玩明白了「怎么打、怎么死、怎么重开」

## 常见坑

1. **碰撞层与掩码搞反（新手第一大坑）**：`collision_layer` 是「我属于哪些层」，`collision_mask` 是「我要检测哪些层」。A 想检测到 B，必须 **A.mask 包含 B.layer**，与 B.mask 无关。`Area2D` 还要区分 `monitoring`（我检测别人）和 `monitorable`（别人能检测我）。查错方法：打开「调试 → 可见碰撞形状」，看颜色和实际接触不一致的地方。
2. **`queue_free()` 是延迟的**：节点在当前帧结束才真正释放，中间还能被访问。用 `is_instance_valid(node)` 判断；要在同一帧立刻消失，先 `remove_child()` 再 `queue_free()`；绝不要在 `queue_free()` 之后继续读写该节点的属性。
3. **暂停时 UI 也被暂停了**：`get_tree().paused = true` 会连 UI 一起冻住。给暂停菜单所在的 `CanvasLayer`/`Control` 设 `process_mode = PROCESS_MODE_WHEN_PAUSED`（或 `ALWAYS`），Autoload 默认是继承，容易一起被冻。改 `process_mode` 后没生效，先检查父节点是不是把它覆盖回去了。
4. **信号重复连接**：每次重进同一场景都 `connect` 一次，于是「一次受击扣 3 次血」。连接前用 `is_connected()` 判断，或优先在**场景里静态连接**而不是运行时用代码连；一次性事件可用 `CONNECT_ONE_SHOT`。
5. **物理帧与渲染帧混用**：在 `_process` 里读物理状态会抖（因为物理可能没更新）；移动、碰撞、命中判定放 `_physics_process`，视觉、UI、相机平滑放 `_process`。混用最典型的症状是「角色在 144Hz 屏幕上贴墙抖动」。
6. **场景切换导致引用失效**：`change_scene_to_file()` 是延迟到帧末执行的，旧节点随后被释放。切场景后仍在跑的回调、`Tween`、存着旧节点引用的 Autoload 会指向已释放对象。Autoload 里只存**数据**（分数、状态枚举），不存节点引用。
7. **`Engine.time_scale` 波及面比你想象的大**：它缩放所有 `delta`，包括 UI 动画、倒计时、粒子和部分计时器行为。不要在慢动作里依赖「真实时间」，`SceneTreeTimer` 是否受暂停/缩放影响有参数可调，具体签名与默认值以当前文档为准。
8. **对象池忘记重置状态**：复用的子弹带着上一发的速度和方向飞出来，或者复用的敌人生成时就是残血。给池化对象写一个 `reset()`，把速度、HP、`visible`、`monitoring`、`set_process` 一次性归位。

## AI 协作提示词

**① 当审查员：只找状态机漏洞，不重写**

```text
下面是我的 GameState Autoload 和它的调用处（贴代码）。
请只做审查，不要重写、不要给我新的实现。要求：
1. 列出所有「从某个状态出发、没有被处理」的事件（例如在结算时按 ESC、暂停时死亡）；
2. 找出可能造成状态残留的地方（time_scale、paused、信号连接、节点引用）；
3. 找出信号可能被重复连接的位置；
4. 每条只给「触发场景 + 现象 + 一行修复方向」。
```

**② 当出题人：用碰撞层出题（我最容易搞混）**

```text
你是 Godot 面试官。我给了 5 个层：Player / Enemy / Wall / PlayerAttack / EnemyAttack，
下面给你我的 layer 和 mask 配置表（贴表）。
不要讲理论，直接出 5 道判断题：给我一个场景（例如「敌方的子弹应该能打到玩家但不能打到敌人」），
问我这组配置会发生什么；一次一题，我答错先给提示。最后给我一份「应该如何配置」的对照表。
```

**③ 当讲师：用 Node 生态类比讲透暂停与时间**

```text
我是 TypeScript/Node 背景，做游戏时对「暂停」和「时间缩放」总是搞混。
请只做讲解，不要写代码，用我熟悉的模型（Node 事件循环的顺序、AbortController、可暂停的任务队列）
类比解释：get_tree().paused、process_mode 的几种取值、Engine.time_scale、delta 是谁给的。
每个概念给 ① 一句类比 ② 一句精确含义 ③ 一个我大概率会踩的坑。
```

# S7 · Steam 上架全流程（3 周 / W16–W18）

> 目标：**把游戏变成一个能卖的商品页面。** 这一关不是技术活，是流程活：注册、税务、商店页、构建上传、审核、Demo。
> 关键认知：Steam 上架的**一半时间花在等待**（税务验证、30 天等待期、14 天 Coming Soon、3–5 个工作日审核）。
> 所以这一关必须**并行推进**：一边做商店页素材，一边等审批，一边准备构建。

> [!note] 数据可信度说明
> 本页数字分两类：**（官方）= Steamworks 文档/官方页面确认；（经验值）= 第三方整理或开发者社区口径，会随时间变化**。
> 时间敏感的数字（榜单门槛、转化率）在 [[S8 营销发售与复盘]] 里统一复核，本页只保留流程必需的硬约束。

> 编号约定：本文件的 W16-D1 ~ W18-D7 指阶段内的周与天，不是全局天数。

## 实战需求

**需求 A：可售卖的商店页终稿（**W6 已公开 Coming Soon**，本关只做素材终稿替换与复核）**

含：名称、短描述（≤300 字符）、长描述、5+ 张截图、至少 1 个预告片/GIF、Capsule 图全套（小/主/头图/库图）、标签（Tags）、系统需求、语言支持表、开发商/发行商名称。

**需求 B：能通过审核的可下载构建**

Windows 构建上传到 Steam、在一个非开发者的机器上验证过、Demo 与正式版分支分离。

**需求 C：合规清单全部打钩**

内容调查表（IARC 分级）完成、隐私政策就位（如适用）、AI 生成内容按政策披露、税务信息通过、银行账户验证通过。

**需求 D：一页《发售倒推表》**

把下面所有等待时间倒排到日历上（这是 S7 最重要的产出）。

## 知识点

### 1. 关键路径与等待期（**先排日程，再动手**）

| 步骤 | 耗时 | 备注 |
| --- | --- | --- |
| 注册 Steamworks + 付 $100 | 当天 | （官方）每个 App **$100**，中国大陆区显示 **¥703** |
| 身份 + 税务验证 | **2–7 个工作日** | （经验值）第三方处理，被退回不代表填错 |
| 首次发行等待期 | **30 天** | （经验值）支付 $100 后起算，这 30 天不可发售 |
| 商店页审核 | **3–5 个工作日** | （经验值）建议提前 7 个工作日提交 |
| Coming Soon 公开期 | **≥ 14 天** | （官方）发售前必须公开满两周 |
| 构建审核 | **3–5 个工作日** | （经验值）审核通过后仍需**手动**点 Release |
| 首次发行总计 | **8–10 周** | （经验值）含上述全部等待 |

> [!important] 与本计划的日历对齐
> 若从 2026-10-05 启动（W1），S7 落在 **2027-01 中旬～02 上旬（W16–W18）**，正好赶在 2 月 Next Fest 前把构建与 Demo 送审通过。
> **但"注册 + 交 $100 + 公开商店页"必须在 W6 完成**——2 月场的报名截止约在 **2027-01-10（W14）**，早于 S7 的起点，那时你还没进这一关。
> **但商店页不该等到 W16 才开**——[[S3 垂直切片与竞品拆解]] 结束时（W6）就该把 Coming Soon 页挂上去，用半年时间攒愿望单。S7 这一关做的是"收尾与合规"，不是"第一次见到 Steamworks"。

### 2. 费用与分账（先把账算清）

| 项目 | 数值 | 说明 |
| --- | --- | --- |
| 上架费 | **$100 / 每个 App**（官方） | 单款**调整后总收入达 $1,000** 后退还；不可跨游戏累计 |
| 分账阶梯 | **30% / 25% / 20%**（官方） | 单款在 Steam 收入 **首 $1,000 万 30%**；$1,000 万–$5,000 万 **25%**；$5,000 万以上 **20%**；**按单产品、不回溯** |
| 计入门槛的收入 | 游戏包 + DLC + 内购 + 社区市场游戏手续费（经验值） | 其他平台/key 收入不计 |
| VAT / 退税 | 都在**分账前**扣除（经验值） | 退款订单不产生 30% 抽成，但那笔毛收入消失 |
| 退款率 | 中位 **9.5%** / 均值 **10.8%**（经验值） | 抢先体验中位 **12.4%**；建模时按 **10%** 预留 |
| 单份到手（模型） | $19.99 定价 → 自发行约 **$7.9/份**（经验值） | 含区域定价与抽成后的估算，仅用于做预算 |

> [!warning] 别用"定价 × 销量"算收入
> 正确算式：**实收 ≈ 定价 × 销量 × (1 − 区域折价影响) × 0.7 × (1 − 退款率) × 0.9**（最后 0.9 为预扣税，见下）。
> 一款 $9.99、卖 1,000 份的独立游戏，实收大概率在 **$4,000–5,000 量级**，不是 $9,990。

### 3. 中国大陆个人开发者：注册 · 税务 · 收款（本页最实操的一节）

**结论：个人可以注册，不需要先开公司。**

**注册要点：**

1. 用**现有 Steam 账号**登录 `partner.steamgames.com` 注册开发者，付 $100。
2. 实名信息**全部用拼音**填写（姓名、地址），与银行/收款账户保持一致——中文填写更容易被反复打回。
3. 准备：身份证 + 一份近期的地址/账户证明（经验值：有人用银行柜台盖章的账户回单通过）。
4. 账户名必须与**收款账户名完全一致**。

**税务（W-8BEN）：**

| 场景 | 预扣税率 |
| --- | --- |
| 不提交税务表 | 默认 **30%**（官方，非美居民默认税率） |
| 提交 W-8BEN，标注非美国税务居民 + **Foreign TIN 填 18 位身份证号** | **(官方)** 有税收协定可适用更低税率；中美协定特许权使用费上限 **10%**（经验值实践：30% → **10%**） |

> [!tip] 这一栏值钱
> 10% 与 30% 的差别直接是收入的 20 个点。**填完务必在后台确认实际适用税率**，不要凭假设。

**收款（经验值，均为社区/服务商口径）：**

| 方式 | 费率/障碍 |
| --- | --- |
| 国内银行收 SWIFT 电汇 | 每中间行扣 **$15–30**；常因无法识别 Valve 汇款性质被**退汇**，退汇双向收费 |
| 第三方收款（如万里汇等） | 提现费率约 **0.7% 封顶**，以服务贸易名义代申报，**不占用个人每年 $50,000 便利化结汇额度** |
| 美国本地账户 | 费率最低，门槛最高 |

- 打款：最低门槛约 **$100**、**按自然月结算、次月支付**（经验值）。
- **不要**为了收款先去注册公司：合规成本（记账、报税）会远超第一款游戏的收入。

### 4. 商店页：玩家只会给你 10 秒

| 位置 | 必须做到 |
| --- | --- |
| **名称** | 好记、可搜索、不与其他游戏混淆（**发布前仍可改但会触发重审，尽量在 W17 定死**） |
| **Capsule 图** | 在 200px 宽下也要能认出题材与风格；这是唯一的"广告位" |
| **前 3 张截图** | 第 1 张必须展示**核心动词**，不要放标题画面或风景 |
| **预告片** | 前 5 秒出现玩法与反馈；无声也能看懂 |
| **短描述** | 一句话说清"你扮演谁、做什么、为什么爽"，不写世界观设定 |
| **标签 Tags** | 决定推荐系统把你分给谁；照抄 3 款竞品的高频标签再筛选 |
| **语言支持** | 只勾你**真的**做过本地化的语言（虚标会被差评） |

**操作顺序**：商店页审核通过 → Coming Soon 公开 → 累计愿望单 → 才能定价与发售（**≥14 天**硬约束）。本计划在 **W6** 完成这一步，见 [[S3 垂直切片与竞品拆解]]。

### 5. 构建上传（SteamPipe / Depot）

- 概念：**App**（商品）→ **Depot**（内容包）→ **Build**（一次上传的版本）。
- 建议：正式版与 **Demo 分成不同 Depot**，用**分支（branch）**做测试版（如 `beta`），不要把测试版本推到 `default`。
- 上传后**不会自动发售**，必须手动点 **Release App**（官方）。
- 每次重大更新前先推 `beta` 分支给几个人验证，再切 `default`。

### 6. Steamworks 功能（要不要接，怎么接）

| 功能 | 第一款游戏 | 接入难度 | 说明 |
| --- | --- | --- | --- |
| **成就** | 建议做 | 低 | 8–15 个即可，是低成本的口碑与留存工具 |
| **云存档** | 建议做 | 低 | 玩家换机器不丢档，差评防御 |
| **Rich Presence** | 可选 | 低 | 显示"正在第 3 关" |
| **创意工坊** | 不做 | 高 | 需要一个内容生态才值得 |
| **排行榜** | 可选 | 中 | 只有玩法天然可竞速时才做 |
| **Steam 输入 API** | 推荐 | 中 | 手柄兼容性的标准答案 |

Godot 用 **GodotSteam**；Unity 用 Steamworks.NET / Facepunch.Steamworks。**在 [[S6 系统层本地化与打包]] 完成存档/设置之后再接**，否则会返工。

### 7. Demo 与 Next Fest（别浪费唯一一次机会）

- **Demo 是 Next Fest 的入场券**：需未发售 + 公开可玩 Demo + 公开预告片（官方）。
- **每款游戏终身只能参加一次 Next Fest**（官方），所以**不要早早上 Demo 去参加**——要在愿望单基数最大时参加。
- Steam 还有**更新曝光轮次**：每款游戏终身 **5 次**，每次最长 30 天或 100 万次首页曝光（先到者止），**仅在发售后的初始曝光结束后可用**（官方）。把它留给发售后的内容更新。
- 具体档期与报名截止见 [[S8 营销发售与复盘]]。

### 8. 合规：内容调查表 · 分级 · AI 披露 · 隐私

- **内容调查表（Content Survey）必须填**，Valve 通过 **IARC** 免费生成分级（ESRB/PEGI/USK 等覆盖区）。**德国自 2023-11-15 起年龄分级为强制要求**（官方公告）。
- 日本 CERO、韩国 GRAC 等**不覆盖、需单独送审**（可能有费用，经验值：CERO 单款费用不低），第一款游戏可以直接选择不在这些区域发售。
- **AI 生成内容披露（政策已明确，务必照做）**：
  - **2024 年**起：提交游戏时必须在内容调查表中申报 AI 使用情况，**说明会公开显示在商店页**。
  - 分两类：**预生成内容**（美术/声音/叙事/本地化/商店素材）必须写说明；**实时生成内容**（运行时动态生成）必须披露**并设置防护措施**，失控会导致下架。
  - **2026-01 更新**：明确**"仅用于提效的幕后 AI 工具"（代码助手、概念图、占位文本）无需披露**；披露聚焦"由玩家消费的 AI 生成内容"。
- **隐私政策**：只在**收集数据或接入第三方 SDK/遥测**时才必须有；纯单机不收集数据可不需要（经验值）。一旦接了就写清楚收集范围、用途、删除方式。
- **版号与国内合规**：
  - Steam **国际版上架不需要中国游戏版号**（律师意见，非官方规则）。
  - **蒸汽平台（Steam 中国）必须取得版号**，且需**单独送审**——不要顺手为了多一个渠道去上。
  - 风险提示：法规未明确禁止个人在境外平台发行，但**不排除**被以"绕过监管"等事由处理；**不要**在国内社交平台公开引导玩家跨区、不要接境内支付。涉及合规细节，**以专业律师/税务意见为准**。

- [ ] 能一口说出：$100 何时退还、分成门槛、退款预估值、实收算式

## 常见坑

1. **中文填实名信息导致反复被打回**：姓名与地址用**拼音**，且必须与收款账户一致。
2. **没填 Foreign TIN 就提交 W-8BEN**：被按 **30%** 预扣，白白少 20 个点，且事后追补麻烦。
3. **等到 W18 才开商店页**：愿望单从零开始，发售时几乎没人知道。**商店页应在 W6 就公开**。
4. **上架费当"沉没成本"**：单款满 $1,000 收入可退 $100，值得为它多推一把。
5. **把测试构建推到 `default` 分支**：玩家会下到半成品。用 `beta` 分支。
6. **审核通过就以为上线了**：必须**手动 Release App**。
7. **AI 披露漏填**：商店页说明与实际情况不符，属于可被下架的问题。**幕后工具不用报，玩家能看到的 AI 内容必须报**。
8. **虚标语言支持**：勾了没做本地化的语言，会直接变成差评来源。
9. **上线前才想起分级**：德国强制分级，没做会直接影响该区发售。
10. **为了"多一个渠道"顺手考虑蒸汽平台**：那边需要版号，是完全不同的一套合规流程。

## AI 协作提示词

**① 当流程审查员（找出你漏掉的合规项）：**
```text
我是中国大陆个人开发者，准备把一款 2D 单机游戏上架 Steam 国际版。
下面是我的准备清单（贴清单）。
请以"Steamworks 审核员 + 税务/合规顾问"的视角，列出我漏掉或写错的项目，
按"会导致无法发售 / 会导致收入损失 / 只是体验变差"三档严重度排序。
不确定的地方明确写"需以官方文档为准"，不要猜政策条款。
```

**② 商店页盲测（把素材描述给 AI 做第一轮筛）：**
```text
这是我一款独立游戏的商店页文案（贴短描述/长描述/标签）。
请扮演一个"只扫 10 秒"的玩家，回答：
1. 你觉得这是款什么游戏？（复述给我）
2. 哪一句让你最想继续看，哪一句是废话？
3. 你会给它加什么标签？我漏了什么标签？
只做诊断给 3 条修改方向，不要替我重写整篇文案。
```

**③ 发售倒推表检查：**

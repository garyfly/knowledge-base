# S5 · 内容量产与打磨（7 周，W8–W14）

> 目标：把垂直切片那"5 分钟最终品质"，变成 **90 分钟完整游戏**。
> **这是整个项目最容易死的阶段**——不是死于技术，是死于：一直在做系统没有内容、数值全靠感觉、最后两周才发现性能问题、只在开发机上测试。
> 这 7 周的性质和前 7 周不同：**写代码少了，做内容多了**。你的角色从"程序员"切换成"流水线厂长 + 质检员"，每天问的不是"这个功能怎么写"，而是"今天产出了多少可玩内容、修了几个 Bug"。

## 实战需求

**需求 A：内容流水线（先模板，后量产）。**

1. 一类关卡/房间/词条只做一个**标准样板**，包含所有元素（地形、敌人、奖励、出口、事件），30 分钟内能复制出一关
2. 数据驱动：配置放进 `Resource`（`.tres`）或 `JSON`/`CSV`，**代码里没有魔法数字**，改内容不改代码
3. 批量生成：脚本（GDScript `@tool`/`EditorScript`，或外部 Python）从表格批量生成内容文件
4. 每周记录 5 项：新增可玩分钟 / 新增关卡数 / 修复 Bug 数 / 是否导出构建 / 本周 Cut 记录

**需求 B：数值与平衡可调。**

- 难度曲线与 **首胜时间**（开局 3 分钟内必须让玩家赢一次）、DPS/经济/成长曲线都有表格支撑
- 用 Google Sheets 或 CSV 调参 → 一键导出到数据目录；关键参数可**热改**，做到"改一个数字，3 秒后看到手感变化"

**需求 C：打磨清单（把"能玩"变成"好玩"）。** 反馈（命中停顿、震荡、闪白、粒子、音效、击退）、转场、加载时间、死亡到重开的循环 ≤ 3 秒，每项打勾或明确写"不做及原因"。

**需求 D：测试与性能。** 一份可执行的自测清单（每条 = 前提/操作/期望）+ 边界情况枚举；崩溃日志能落盘回收；Godot Profiler / Monitors 看过帧率、对象数、孤立节点无持续增长。

**需求 E：W8 起每周五都做 Cut 决策。** 对照 [[附录 C 范围与功能裁剪决策卡]] 过一遍，砍掉的写进 GDD 的 Not Doing 一节，**砍完不再讨论**。

## 知识点

| 知识点 | 一句话定义 | 在本项目怎么用 | 要能回答 |
| --- | --- | --- | --- |
| 内容模板 | 一类内容的"填空题"样板，可批量复制 | 房间数/敌人位/奖励位固定，只填数据 | 你复制一关需要几步、几分钟？ |
| 数据驱动与批量生成 | 用数据而不是代码描述内容，并由脚本产出 | `.tres`/JSON/CSV + `@export` + 生成脚本 | 加一个新敌人要改几个文件？生成物怎么保证可玩？ |
| 难度曲线与首胜时间 | 难度随进度的上升节奏；首次获胜的耗时 | 时间/关卡序号映射敌人强度；前 3 分钟给一次明确胜利 | 难度是"感觉难"还是"算出来的"？为什么先赢一次比先教操作重要？ |
| 经济 / DPS 曲线 | 收益与输出的增长速率 | 表格记录每阶段数值并画折线 | 玩家会不会中期"钱多到没处花"？ |
| 热改参数 | 不重启就改数值 | debug 面板 / 重载数据文件 | 改一个数值到看到效果要多久？ |
| 打磨（Polish）与打击感（Juice） | 让同一玩法"手感变好"的所有小工作；输入→反馈的密度 | 命中停顿、震动、闪白、粒子、音效叠加；按清单打勾 | 举例 5 个提升打击感的手段；为什么命中停顿用帧数不用秒？ |
| 转场 | 场景切换的视觉过渡 | 淡入淡出/滑动，时长要短、可跳过 | 转场太长怎么影响重开体验？ |
| 自测清单与边界情况 | 可逐条执行的验证步骤 + 极端输入 | 每条写清前提/操作/期望；枚举满/空/连按/失焦/坏存档 | 你的清单里有几条"边界情况"？ |
| 性能剖析与对象泄漏 | 测量帧时间与对象数；该释放的节点没释放 | Profiler/Monitors 面板；检查未 `queue_free()` 的实例 | 是 CPU 还是 GPU 卡？怎么发现"每关多 200 个对象"？ |
| 范围蔓延 | 不断加功能导致做不完 | 每周 Cut + Not Doing 清单 | 第 10 周落后 30%，你砍什么？ |

### 用表格调参，不要改代码

| 做法 | 迭代速度 | 风险 |
| --- | --- | --- |
| 数值写在 GDScript 常量里 | 改代码 → 重启 → 走到那一关（分钟级） | 慢到你会放弃调参 |
| 数值放 `Resource` / `@export`，编辑器里改 | 秒级 | 场景文件易冲突，注意提交粒度 |
| 数值放 CSV/JSON，一键导入 + 运行时热重载 | 秒级，还能交给别人填 | 要写导入与校验，格式错必须报错清晰 |
| **推荐组合** | CSV 为真源 → 导入成 `.tres`/JSON → 运行时热重载 | 加"数据校验"步骤：缺字段直接报错 |

> [!tip] 首胜时间为什么是硬指标
> 玩家前 3 分钟决定要不要继续玩。**让他赢一次**（哪怕是安排好的必胜开局）比教他 10 个按键更有效——先给爽感，再给复杂度。这也是 [[S2 核心循环与有趣度设计]] 里"30 秒爽感"在量产阶段的延续。

## 验收标准

- [ ] 从新档到通关（或完成一局完整循环），**连续 60~90 分钟不崩溃、不卡死、无未登记的占位素材**（每个占位物都在待替换清单里，且清单已清空或有明确原因）
- [ ] 前 3 分钟内发生一次明确胜利（不看攻略、不需你解释）
- [ ] 加一个新敌人/新关卡**只改数据文件**，不改任何 GDScript 逻辑
- [ ] 改一个数值到看到效果 ≤ 3 秒（热改可用）
- [ ] 难度曲线能画出来，≥ 3 处调整有"试玩 → 数据 → 修改"的记录，而非"感觉"
- [ ] 打磨清单打勾率 ≥ 80%，未做项都有明确原因（写进 Not Doing）
- [ ] 死亡→重开 ≤ 3 秒；连续重开 10 次不累积卡顿
- [ ] 60 FPS 目标下 1% Low 帧时间无持续尖峰；连续游玩 60 分钟对象数不持续增长
- [ ] 自测清单每条都跑过并留痕（日期 + 结果）；边界情况全部有结论；崩溃日志含足够定位信息
- [ ] ≥ 3 台不同配置机器（含一台核显/老笔记本）安装运行通过，30/60/144Hz 都试过
- [ ] W8 起每周一次 Cut 决策有记录，累计 ≥ 5 次；构建按周存档

## 常见坑

1. **前 10 周都在做系统，没有内容**：系统的价值只在内容里体现。**W8 起每周期待产出可玩分钟数**，不是功能数。
2. **数值全靠感觉**：改完就试玩、试玩就忘。没有表格与记录，三个月后不知道调过什么。
3. **手工堆内容 / 内容硬编码**：第 20 关还在手摆地形、加一关改一次代码。**模板没做好不许开始量产**。
4. **后期才发现性能问题**：粒子、大量节点、频繁 `instantiate` 的代价在内容量上来后才暴露。W8 起每周看一眼，别等 W13。
5. **只在开发机上测试**：你的机器是最优配置。至少 3 台 + 不同分辨率与帧率。
6. **后期改数据/存档格式**：W12 才换格式会导致前面内容重做。**W8 冻结数据表/关卡格式；存档格式在 S6 开工时冻结**，之后只加字段不删字段。
7. **打磨被内容挤掉**：砍内容不砍打磨。30 分钟精致的小游戏 > 3 小时粗糙的半成品。
8. **忘了 `queue_free()`**：敌人死亡只隐藏不释放，跑几关帧率崩。用 Monitors 的对象数曲线抓。
9. **没有 RC 冻结**：改到发售前一天，构建不可信、Bug 不收敛。W14 冻结，之后只修 Bug。
10. **本地化最后才做**：所有玩家可见文本从 W8 起就走 key，别等 [[S6 系统层本地化与打包]] 再回头捞。

> [!warning] 如果第 10 周进度落后 30%，按这个顺序降级（先砍前面的）
> 1. **砍内容量**：90 分钟 → 45–60 分钟；砍掉重复度最高的关卡/区域（每种玩法各留 2 关）
> 2. **砍系统**：Should 圈全部进 Cut；只留 Must 圈，半成品代码直接禁用而不是删干净（省时间，但注意别留 Bug）
> 3. **砍美术**：复用既有素材 + 换色调做"新敌人"；减动画帧数；用纯色/几何体替代新绘制资产
> 4. **绝不砍**：打磨（反馈/手感）、测试、性能修复、可运行版本——砍这些等于把"做完了"变成"没做完"
> 降级方案写进 GDD 的 Not Doing 一节，并对照 [[S3 垂直切片与竞品拆解]] 的试玩反馈：如果陌生人抱怨的是手感而不是内容量，说明你砍错了地方。

## AI 协作提示词

**① 生成批量内容脚本（只给脚本，不要替我设计玩法）：**
```text
我的关卡数据格式如下（贴 JSON schema 或一行样例 CSV）。
请写一段 GDScript（或 Python）脚本，从 CSV 生成 N 个关卡数据文件，要求：
每行做字段校验（缺字段/超范围时报出文件名+行号）、固定随机种子可复现、不引入第三方依赖。
不要改变我的字段含义，不要替我设计关卡内容。
```

**② 让 AI 当"关卡审稿人"而不是设计师：**
```text
这是一关的配置数据（贴 JSON）和我的规则（贴 3~5 条：房间数上限、敌人密度、奖励间隔）。
请只做检查：哪些数值违反了规则？哪些组合可能让玩家无解或卡死？
每条格式：问题 / 触发条件 / 建议检查方向。不要重写这关，也不要发明新机制。
```

**③ 用 AI 找边界情况：**
```text
我的游戏规则是（贴核心循环与系统清单：战斗/背包/存档/暂停/切场景）。
请列出我可能没测到的边界情况，至少 15 条，按"最容易出严重 Bug"排序，
每条给出：操作序列 / 期望 / 可能的现象。不要给修复代码。
```

**④ 让 AI 审查平衡数据（不替我拍板）+ 打磨自查：**
```text
这是我的成长曲线表（贴每阶段 DPS/血量/掉落/耗时）和打磨清单当前状态（贴表格）。
请指出：① 哪些区间增长率异常（突然变陡或变平）、哪阶段收益溢出或卡住、哪些数值会让"跳过某系统"成为最优解；
② 哪些项我标了"已做"但看不出可验证证据、哪类反馈（视觉/听觉/位移）明显偏少。
只给异常点、验证方法和"如果只能再做 3 项"的排序理由，不要直接给我新数值。
```

# S6 · 系统层本地化与打包（第 15 周，1 周）

> 目标：把"在我电脑上能跑"变成"**别人的电脑上装了就能玩、玩完关掉、下次打开还在**"。
> 这一周做的东西玩家平时不会夸，但只要做错，他们会立刻打差评：**存档丢了、设置不记住、中文变方框、4K 屏幕 UI 糊成一团、双击 exe 报缺 DLL。**
> 上一阶段 [[S5 内容量产与打磨]] 产出的是"游戏内容"，这一周产出的是"**产品的壳**"。壳有洞，内容再好也漏光。

## 实战需求

**需求：为已完成的游戏做出一个"可交付给陌生人的 Windows 构建"，包含存档、设置、双语、可访问性四件套。**

具体验收：

1. **存档系统**：至少 3 个存档槽 + 1 个自动存档位，存档写在 `user://`，带版本号字段；游戏升级后旧存档能继续用（或安全降级并提示），删掉存档文件游戏能正常新开而不是崩溃。
2. **设置菜单**：分辨率 / 窗口模式 / 垂直同步 / 主·音乐·音效三组音量 / 帧率上限 / 按键与手柄重映射，**每一项关闭游戏再打开后仍然生效**。
3. **双语**：简体中文 + English 两套文案，全部从代码里抽到 CSV，切换语言后 UI 无溢出、无方框；游戏内可实时切换。
4. **可访问性**：**必做 4 项**——色盲友好、屏幕震动可关闭、字幕、文字大小可调（其余如单手可玩、闪光强度提示列为可选）。
5. **发布构建**：一个安装感的文件夹版 exe + 一个免安装 zip；带图标与启动画面；设置页显示版本号；崩溃日志写到 `user://logs`；游戏内有"反馈 Bug"入口。

## 知识点

| 知识点 | 你可能的第一反应（TS/Node 视角） | Godot / 游戏里的真实含义 | 要能回答 |
| --- | --- | --- | --- |
| `user://` vs `res://` | 路径就是个字符串 | `res://` 是只读的安装目录（导出后可能被打包进 exe）；`user://` 是系统给每个用户的可写目录 | 为什么存档绝对不能写 `res://`？ |
| 存档格式 | JSON 最省事 | JSON（可读、易迁移、易被改）/ 二进制（小、快）/ 自定义 Resource（能用编辑器可视化编辑，但版本迁移更麻烦） | 为什么第一款游戏选 JSON 就够？ |
| 版本迁移 | 数据库 migration | 存档里写 `version` 字段，读取时按版本走升级分支，读不出来的字段一律给默认值 | 旧存档缺一个新字段时会怎样？ |
| `TranslationServer` | i18n 库 | Godot 的翻译服务，配合 CSV/PO 资源与 `tr()` 取文案；节点上可直接挂自动翻译属性 | 文案为什么不能硬编码在字符串里？ |
| 字体与缺字 | 系统有字体就行 | 导出的游戏不会带系统字体，中文/日文需要显式打包字体资源并配置 fallback，缺字渲染成方框（tofu） | 为什么开发机上好好的，玩家机器上是方框？ |
| 锚点与容器 | Flexbox 自动适应 | Godot 用 Anchor/Container 布局；用绝对像素坐标写 UI 就会在别的分辨率错位 | 为什么 1080p 正常、4K 就错位？ |
| 帧率与垂直同步 | requestAnimationFrame | `vsync`、`max_fps`、物理帧率是分开的；帧率上限影响发热与手感 | 高刷屏上为什么游戏"跑得太快"？ |
| 导出模板 | `npm run build` | Godot 导出需要**预先下载对应版本的导出模板**，模板版本与引擎版本不匹配会导出失败 | 换引擎小版本后为什么导出报错？ |
| 崩溃日志 | try/catch + 日志文件 | 游戏崩溃时系统不会自动帮你留日志，需要自己写文件日志 + 全局错误处理 | 玩家说"闪退"，你怎么拿到信息？ |

> [!important] 这一周的铁律：**凡是玩家能改的东西，都必须写回磁盘。**
> 存档、设置、进度、解锁、音量、键位——任何一个"重启就恢复默认"，都是差评来源。

## 关键决策速查（哪条拿不准翻哪条）

| 决策点 | 第一款游戏的建议 | 理由 |
| --- | --- | --- |
| 存档格式 | **JSON** | 可读、好调试、版本迁移最容易；体积在第一款游戏里不是问题 |
| 什么时候用自定义 Resource 存档 | 需要大量策划可视化的数据（关卡/物品表）时 | 编辑器里能直接改，但新增字段的兼容处理要自己写；以官方文档为准 |
| 存档写在哪 | `user://saves/` | 安装目录可能无写权限，且卸载会带走存档 |
| 自动存档时机 | 进入新关卡 + 暂停 + 定时（如 2 分钟） | 覆盖式自动档要保留至少一个"上一次手动档" |
| 首发语言 | **简体中文 + 英文** | 其他语言等有销量数据再补，翻译质量比数量值钱 |
| 分辨率策略 | 逻辑分辨率 + 缩放（像素风保持整数倍） | 避免高分辨率下像素错位与 UI 错乱 |
| 帧率上限 | 提供 30/60/120/不限 可选 | 高刷屏无上限会发热、耗电，笔记本玩家很在意 |
| 启动画面 | 保留，但可跳过（≤3 秒） | 启动画面是品牌感，太长会被嫌弃 |
| 崩溃日志 | 固定写 `user://logs/`，启动时清理超过 N 天的 | 玩家报 Bug 时你只需要他发一个文件夹 |
| Bug 反馈入口 | 设置页放邮箱 + Discord 链接 + 版本号 | 玩家愿意反馈，但不愿意去论坛注册 |
| 防作弊/存档加密 | **不做** | 单机游戏改档是自由，投入产出比极低 |
| 云存档 | 排在本地存档完全可靠之后 | 本地存档丢档是 P0，云存档是 P1 |

## 验收标准

- [ ] **设置持久化**：改任意设置 → 关闭游戏 → 重新打开，设置仍然生效（逐项验证，不只测音量）
- [ ] **存档安全**：删除 `user://` 下所有存档文件后启动游戏，能正常开始新游戏且不报错
- [ ] **版本迁移**：手工把存档 `version` 改成旧版本号并删掉一个字段，游戏仍能加载（缺字段走默认值）
- [ ] **双语无溢出错字**：中文与英文来回切换 3 次，所有 UI 无溢出、无方框、无未翻译的英文残留
- [ ] **缩放正确**：在 1080p 与 4K（或模拟 4K 分辨率）下，UI 元素不重叠、不超出屏幕、文字清晰
- [ ] **纯净运行**：把 zip 解压到一台**没装过 Godot** 的电脑上，双击 exe 无需任何额外依赖即可运行
- [ ] **崩溃可追溯**：手动触发一次错误，`user://logs` 下有对应日志文件，版本号能对应到构建
- [ ] **可访问性可验证（逐项列出必做 4 项）**：① **色盲友好**：色盲模式开启后关键 UI 元素不只靠颜色区分（截两张图对比）；② **屏幕震动可关闭**：能完全关闭，关闭后无任何震动；③ **字幕**：关键音效/语音有字幕，且字幕可开关；④ **文字大小可调**：调大后 UI 不溢出、不重叠、不超出屏幕
- [ ] 不安装任何运行库、不弹缺 DLL 报错；不同机器上都能进主菜单

> [!tip] 验收要"客观到别人能替你跑"
> 上面每一条都写成了"做什么 → 看什么现象"，因为这些是**上架硬门槛**，不是感觉。自己测完，再找一个没参与开发的人照单跑一遍，见 [[S7 Steam 上架全流程]]。

## 常见坑

1. **把存档写进安装目录**：导出后安装目录通常无写权限（尤其 `C:\Program Files`），写入直接失败或静默丢弃。**一切运行期产生的数据都进 `user://`。**
2. **`user://` 与 `res://` 混淆**：`res://` 导出后可能被压进 pck，路径不再对应真实文件；用 `FileAccess` 操作 `res://` 写入必然失败。
3. **导出后资源路径全部失效**：用绝对路径（`E:/项目/...`）加载资源，开发机没问题，导出后全找不到。一律用 `res://` 相对路径与 `preload`/`load`。
4. **字体没打包进导出**：导出预设里没勾选/没包含字体文件，或只依赖系统字体 → 玩家机器上中文全变方框。中文字体体积大，注意构建体积与 [[S4 资产管线与美术音频]] 的授权清单。
5. **UI 用绝对像素**：`position = Vector2(1730, 940)` 在别的分辨率直接飞出屏幕。用锚点 + 容器 + 尺寸策略。
6. **只装了开发机上的运行库**：开发机预装了 VC++ 运行库、.NET 等，玩家机器是干净的。**一定要在干净机器/虚拟机/朋友电脑上试跑。**
7. **导出模板版本不匹配**：引擎升级了小版本但没更新导出模板，导出直接失败或产出无法运行的包。**换版本就重新下载模板。**
8. **只测了窗口模式**：全屏切换、Alt+Tab、双屏、切分辨率后 UI 错位，都是高频差评点，必须专门测。
9. **存档只写不读校验**：JSON 被玩家手改或写入中途断电导致文件损坏，读取时直接崩溃。读取必须能容忍异常并降级到新档。
10. **本地化只翻了主菜单**：游戏内提示、物品描述、报错文本还是硬编码英文，切换语言后中英混杂。

> [!warning] 第一款游戏不要做的两件事
> **① 防作弊/存档加密**：单机游戏改存档是玩家的自由，加密只会让你自己维护成本暴涨，还挡不住任何人。**② 云存档**：GodotSteam 云存档可以做，但排在"本地存档绝对可靠"之后，见 [[S7 Steam 上架全流程]]。

## AI 协作提示词

**让 AI 当存档系统审查员：**
```text
下面是我的 Godot 存档管理脚本（贴你的代码）。
场景：单机 2D 游戏，JSON 存档写在 user://，已经有 version 字段。
请只做审查不要重写，指出：① 哪些情况会导致存档损坏或读取崩溃 ② 版本迁移缺失的分支
③ 自动存档可能覆盖掉玩家好档的风险点。每条给出"怎么复现"。
```

**让 AI 出本地化排错题：**
```text
我在做 Godot 4 的中英双语。现在的问题是：开发机上中文正常，导出给朋友后中文变成方框。
我试过：把 ttf 放进项目、在主题里设置了默认字体。
不要直接给我答案，先给我 5 个排查步骤（从最可能到最不可能），我做完再问你下一步。
```

**让 AI 帮我做可访问性清单：**
```text
这是我这款游戏的核心玩法与 UI 描述（贴你的玩法陈述 + UI 截图描述）。
请列出适用于这类游戏的 10 条可访问性改进项，按"实现成本低→高"排序，
每条说明：玩家受益点、大概实现工作量（以小时计）、能否在 1 周内做完。
不要展开成教程，只要清单。
```

**让 AI 审查打包清单：**
```text
这是我要发布到 Steam 的 Windows 构建的导出设置与目录结构（贴截图/描述）。
请对照"一个陌生玩家能不能双击就玩"这个目标，列出我可能漏掉的东西，
包括：图标、启动画面、版本号显示、日志位置、运行库依赖、首次启动体验。
按"会导致玩家无法运行"和"只是体验差"两类分开列。
```

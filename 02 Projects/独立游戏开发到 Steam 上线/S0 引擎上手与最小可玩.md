# S0 · 引擎上手与最小可玩（1 周）

> 编号约定：D1 = 本阶段第 1 天，不是全局第 1 天。

> 目标：7 天内跑通「从想法到能发给朋友的 exe」这条完整闭环。不追求好玩，只追求**完整**——一个做完的小游戏 > 一个没做完的好想法。
> 你会写代码，缺的不是语法，是引擎心智：一个想法在 Godot 里从哪个文件开始、到哪个文件结束。

> [!important] 这一周只学 4 件事
> 节点与场景树、脚本生命周期（`_ready` / `_process` / `_physics_process`）、信号（signal）、导出 exe。
> 其余一切（3D、Shader、联机、动画状态机、设计模式、插件生态）本周全部进 Cut 列表。

## 实战需求

**做一个 60 秒小游戏《躲方块》：完整可玩、可导出、可发给朋友。**

规格照做，本周不自己加需求：

| 项 | 要求 |
| --- | --- |
| 画面 | 2D，窗口 1280×720，纯色几何图形或像素风都可以 |
| 操作 | 左右移动（方向键或 AD），再加一个动作键（跳跃/冲刺，二选一） |
| 玩法 | 玩家在底部左右移动，躲避从上方持续下落的方块；碰到扣 1 血，共 3 血 |
| 时长 | 单局 60 秒；倒计时归零或血量归零即结算 |
| 结算 | 显示存活时间与闪避数；按 R 立即重开，且状态完全重置 |
| UI | 左上角血量、顶部倒计时，**中文**文案 |
| 音频 | 至少 1 个音效（受击或得分），可用免费素材 |
| 交付 | 导出一个能在别人 Windows 电脑上双击运行的文件夹 |

**需求 B（贯穿全周的元需求）**：从 D1 起用 Git 管理项目，每完成一天打一个 commit，message 写清「今天搞懂了什么」。二进制素材走 Git LFS，见 [[01 Notes/框架与工具/游戏开发技术栈]]。

## 知识点与对照

| 引擎概念 | 你的 TS/Web 直觉 | 在 Godot 里真实是什么 | 要能回答 |
| --- | --- | --- | --- |
| 项目结构 | 一个文件夹 + `package.json` | `project.godot` 是根，`res://` 指项目根，文件即资源 | `res://` 与 `user://` 各用来干什么？ |
| 节点 Node | 一个组件 / DOM 元素 | 引擎里最小的功能单元，自带变换、生命周期、能挂脚本 | 「节点」和你说的「对象」差在哪？ |
| 场景 Scene | React 组件 / 一个模块 | 一棵可保存、可复用的节点树，存成 `.tscn` | 什么时候把一棵子树拆成独立场景？ |
| 脚本挂节点 | `new MyClass()` | `.gd` 继承某节点类型，挂上后 `self` 就是这个节点 | 同一脚本挂两个节点，它们是同一份数据吗？ |
| `_ready()` | `componentDidMount` | 节点进入场景树后调用一次，子节点先于父节点 | 为什么 `@onready` 变量在这里能用、在 `_init` 里不能？ |
| `_process(delta)` | `requestAnimationFrame` | 每个**渲染帧**调一次，`delta` = 上一帧耗时（秒） | 不乘 `delta` 会发生什么？ |
| `_physics_process(delta)` | 固定步长的 `setInterval` | 固定频率（默认 60 次/秒）调一次，物理与移动放这里 | 为什么移动要放这里而不是 `_process`？ |
| `signal` | `EventEmitter` / 事件总线 | 节点自带的观察者机制，`connect` 订阅、`emit` 广播 | 什么时候用信号解耦，什么时候直接调函数？ |
| 场景实例化 | `<MyComponent />` | `PackedScene.instantiate()` 后必须 `add_child()` 才是活的 | 为什么 `add_child` 之前访问子节点会报错？ |
| 导出 Export | `npm run build` | 导出预设 + 导出模板，把资源打包成 exe/pck | 导出模板版本不匹配会怎样？ |
| 路径 | `node:path` | `res://` 只读、`user://` 可写，运行时不拼绝对路径 | 为什么 `"C:/Users/..."` 在别人机器上必炸？ |

> [!tip] 一句话记生命周期
> `_init`（构造，节点还没进树，拿不到子节点）→ `_ready`（进树一次，可以安全拿子节点）→ `_process` / `_physics_process`（每帧）→ `_exit_tree`（离开树）。
> 类比：构造函数 → `useEffect(..., [])` → `requestAnimationFrame` 循环 → 组件卸载清理。

## 常见坑

1. **不乘 `delta` 的帧率 bug**：`position.x += 5` 在 60Hz 和 144Hz 机器上速度差 2.4 倍。随时间变化的量要么放进 `_physics_process`（固定步长），要么乘 `_process(delta)` 的 `delta`；物理移动一律进 `_physics_process`。
2. **导出模板没下载 / 版本不匹配**：报 "No export template found"，或导出的 exe 起来是空壳。去「编辑器 → 管理导出模板 → 下载并安装」，必须与编辑器**同一版本**；具体下载方式以当前官方文档为准。
3. **中文显示成方框**：默认字体不含 CJK 字形。导入含中文的 `.ttf/.otf`（如思源黑体 / Noto Sans SC，注意 OFL 授权与署名），在「项目设置 → GUI → Theme → Default Font」指定（具体项名以当前版本文档为准）；导出时字体会自动打包，不用手动拷。
4. **路径写绝对路径**：`"C:/Users/me/...\save.json"` 在别人机器上必炸。读资源用 `res://`，写存档/设置用 `user://`；永远不要用字符串拼系统路径。
5. **Godot 3 教程与 Godot 4 API 不兼容**：最典型是信号写法 `connect("hit", self, "_on_hit")`（3.x）vs `hit.connect(_on_hit)`（4.x），以及 `KinematicBody2D` → `CharacterBody2D`。看到教程先确认版本，报 "invalid call" 先怀疑这个。
6. **在系统文件管理器里移动/重命名文件**：`.tscn` 里的引用会断，场景直接打不开。一律在 Godot 的 FileSystem 面板内操作（较新的 4.x 会为脚本生成 `.uid` 文件，也依赖这套引用，以你当前版本为准）。
7. **改了代码没生效**：场景没保存就按 F5，或运行的是主场景而不是你在改的场景。F5 跑主场景、F6 跑当前场景，改完先 Ctrl+S。
8. **待机时风扇狂转**：没限制帧率。设置 `Engine.max_fps` 或开垂直同步，别让一个静止的小游戏吃满 CPU。

## AI 协作提示词

**① 当讲师：用 React/Node 类比讲引擎概念（明确不许写代码）**

```text
我是有多年 TypeScript/Node 经验的开发者，从没做过游戏，现在用 Godot 4 + GDScript 做第一个 2D 小游戏。
请只做讲解，不要给我任何代码：
用我熟悉的类比（React 组件树、EventEmitter、requestAnimationFrame、npm run build）解释下面 4 个概念，
每个给出 ① 一句类比 ② 一句「在 Godot 里它精确指什么」 ③ 一个我最可能犯的具体错误。
概念：场景与节点树、脚本挂载与实例、signal、_process 与 _physics_process 的分工。
```

**② 当审查员：只诊断，不重写**

```text
下面是我写的 player.gd（贴代码 + 贴报错原文）。
请只做代码审查，不要重写、不要给我修改后的完整文件。要求：
1. 指出所有会导致「帧率相关行为不一致」的地方（该乘 delta、该放 _physics_process 而没放）；
2. 指出生命周期职责错位（_ready/_process/_physics_process 用错位置）；
3. 指出信号连接可能重复的位置；
4. 每条只给「现象 + 一行修复方向」，不要给实现。
```

**③ 当出题人：每天 5 题**

```text
你是游戏引擎面试官。我今天学了 Godot 的节点树、_ready/_process/_physics_process、signal、导出流程。
不要给教程，直接出 5 道场景判断题：每道给我一小段有 bug 的 GDScript 或一个现象描述，
让我判断「会发生什么、为什么、怎么查」。一次只问一道，我答完再问下一道；
我答错时先给提示，不要直接给答案。最后统计哪一类概念最薄弱。
```

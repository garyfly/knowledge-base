# S4 · 数据库与 ORM（2 周）

> 目标：把 S2 的内存仓库换成真正的 PostgreSQL，并**看懂你的每一次查询值多少钱**。
> 这是前端转后端最关键的一关：数据建模错了，后面所有代码都在还债。

## 实战需求

1. **环境**：用 Docker Compose 起 PostgreSQL（外加一个 pgAdmin 或直接用 `psql`），禁止本机裸装
2. **建模**：把 `kb-api` 的内存模型落成表：`users` / `notes` / `tags` / `note_tags`，写清字段类型、约束、外键级联策略
3. **迁移**：用 Prisma Migrate 管理 schema 演进；演示一次"加字段不破坏线上数据"的安全迁移
4. **种子数据**：`seed.ts` 生成 1 万条笔记 + 20 个标签 + 100 个用户，供性能实验
5. **事务**：实现"创建笔记 + 关联标签 + 写审计记录"的原子操作；演示部分失败时全部回滚
6. **查询优化**：找出并修复至少 3 个 N+1，写出 `EXPLAIN ANALYZE` 前后对比
7. **索引**：为"按 userId + createdAt 排序分页"建复合索引，证明它被用上了（对比有无索引的耗时）
8. **软删除与唯一约束**：`deletedAt` 下的邮箱唯一性怎么处理（部分索引）
9. **手写 SQL 练习**：用 `psql` 手写 5 条查询（含 JOIN、GROUP BY、窗口函数各一），不依赖 ORM
10. **备份恢复**：`pg_dump` 备份 + 恢复到新库，验证数据完整

## 知识点与前端对照

| 知识点 | 前端视角 | 后端本周要掌握 |
| --- | --- | --- |
| 关系建模 | 有 TS interface 就行 | 1:1 / 1:N / N:M、范式与反范式的取舍、外键与级联 |
| 类型映射 | TS 类型 | 数据库类型选择：`text` vs `varchar(n)`、`timestamp` vs `timestamptz`、`jsonb`、`uuid` vs bigint |
| 迁移 | 改代码就完了 | schema 即契约，线上数据不能丢；`add column not null` 为什么要给默认值 |
| ORM | 一个查询函数 | ORM 生成什么 SQL、何时该绕过 ORM 手写 SQL |
| N+1 | 没听过 | 循环里查库 → 1+N 次往返，是后端性能事故第一来源 |
| 事务 | 前端没有 | ACID、隔离级别、行锁、死锁、长事务的危害 |
| 索引 | 没听过 | B-tree、复合索引最左前缀、选择性、写放大的代价、`EXPLAIN` 怎么看 |
| 连接池 | 没有 | 连接数与并发、`too many clients`、Prisma 连接池配置 |
| 游标分页 | `slice()` | 深分页 `OFFSET 100000` 为什么慢，keyset 分页怎么做 |
| 并发写 | 无 | 丢失更新、乐观锁（version 字段）与悲观锁（`SELECT FOR UPDATE`） |

## 常见坑

1. **本机裸装 PostgreSQL** —— 版本污染、卸载困难，一律用 Docker。
2. **`prisma migrate dev` 用在生产** —— 生产只跑 `migrate deploy`；`dev` 会尝试重置。
3. **忘记处理 `BigInt` 序列化** —— `JSON.stringify(1n)` 会抛错，Prisma id 用 BigInt 时会踩。
4. **时区**：一律 `timestamptz`，存 UTC，展示层转本地；用 `timestamp without time zone` 迟早出事故。
5. **`findMany` 不带 `select`** —— 把整行（含大文本字段）全查出来，列表接口瞬间变慢。
6. **在循环里 `await prisma.xxx.create`** —— N 次往返；用 `createMany` 或 `$transaction`。
7. **长事务持锁**：事务里做 HTTP 请求 / 发邮件 = 锁被长期持有，连接池耗尽。
8. **唯一索引 + 软删除冲突** —— 已删除的记录仍占用邮箱，需要条件唯一索引。
9. **连接池打满** —— 每个请求都 `new PrismaClient()`，必须单例。

## AI 协作提示词

**建模评审：**
```text
这是我的 ER 设计（贴 Prisma schema）。
假设产品三年后会有：多端同步、版本历史、团队共享笔记、按标签的推荐。
请指出我现在的 schema 在哪些地方会阻碍这些需求，最多 4 条，每条给出"最小改动方向"。不要给完整 schema。
```

**SQL 教练（关键：让 AI 出题我写，而不是它写我看）：**
```text
基于我的 schema（贴表结构），给我 5 道 SQL 练习题：难度递增，覆盖 JOIN、聚合、窗口函数、CTE、upsert。
只给题目和预期答案的字段名，不要给答案。我写完发给你，你再逐条批改。
```

**性能诊断扮演：**
```text
这是我的一条查询和 EXPLAIN ANALYZE 输出（贴出来）。
请解释执行计划里每一步在做什么，指出性能瓶颈在哪，
并给出 2 个候选优化方向及其预期代价（不要直接给最终 SQL）。
```

**事务与并发：**
```text
用"两个人同时编辑同一篇笔记"这个场景，解释丢失更新是怎么发生的，
并从乐观锁、悲观锁、串行化隔离级别三种方案里选，说明各自适用场景。
给一个能复现问题的测试脚本思路（用两个并发请求），不要完整代码。
```

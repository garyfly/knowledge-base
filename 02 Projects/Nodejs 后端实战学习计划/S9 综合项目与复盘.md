# S9 · 综合项目与上线（3 周）

> 目标：**从零到公网，独立交付一个完整产品**，并把它变成你简历和面试的主战场。
> 这一关不学新技术（除非是产品必需），只练"把学过的东西组合起来并交付"。

## 一、选题要求

必须同时满足四条：

1. **你自己会用**（每天或每周会打开，否则第 3 周一定放弃）
2. **需要登录 + 数据持久化**（否则用不上 S3/S4）
3. **至少有一个"实时"或"异步"特性**（否则用不上 S5/S6）
4. **能公网访问**（否则用不上 S8）

推荐选题（来自 [[README]] 第 6 节）：

| 选题 | 主考知识点 | 难度 | 3 周可行性 |
| --- | --- | --- | --- |
| **团队看板（类 Trello）** | 实时协作、权限模型、事件顺序 | ⭐⭐⭐⭐ | 够（可裁剪拖拽动画） |
| **内容聚合 / RSS 阅读器** | 定时抓取、队列、去重、缓存 | ⭐⭐⭐ | 高 |
| **个人知识库同步服务** | 全文检索、版本历史、冲突合并 | ⭐⭐⭐ | 中（检索需额外学） |
| **小程序/管理后台后端** | 最贴近就业、CRUD + 权限 | ⭐⭐⭐ | 高（需自备前端） |

**建议**：选 `团队看板` 或 `内容聚合`。前者面试故事更好讲（并发与一致性），后者更省时间。

## 二、需求拆解（第 1 周前半必须完成）

用"用户故事 + 验收标准"写，不写技术方案：

```markdown
## 用户故事
- 作为普通用户，我能注册并创建自己的看板
- 作为看板成员，我能看到别人实时添加的卡片
- 作为看板管理员，我能移除成员
- 作为用户，我能导出看板为 JSON（异步任务）

## 非功能需求（这一栏最容易被忘，也最出彩）
- 一个看板 50 人同时在线不卡
- 接口 P95 < 300ms（本地压测）
- 数据每天自动备份，可恢复到任意一天（实现到"最近 7 天"即可）
- 部署后 5 分钟内完成一次发布
```

**范围控制铁律**：列 20 个功能，**只做 8 个**，其余进 `BACKLOG.md`。宁可小而完整，不要大而未完成。

## 五、技术复盘模板

```markdown
# 项目技术复盘：<项目名>

## 1. 做成了什么（一句话 + 数据）
例如：支持 50 人并发协作的看板，P95 210ms，日均 200 请求。

## 2. 架构
（贴架构图）关键决策 3 条 + 各自理由。

## 3. 我踩过的 3 个最深的坑
| 现象 | 根因 | 怎么定位 | 怎么修 | 如何预防 |
| --- | --- | --- | --- | --- |

## 4. 性能数据
| 优化项 | 前 | 后 | 方法 |

## 5. 如果重做一次，我会改什么
（必须写 3 条，且不能是"多写测试"这种空话）

## 6. 已知问题与技术债
（诚实写，面试官反而加分）

## 7. 下一步演进计划
（比如：多租户、搜索、限流精细化、K8s —— 说明为什么现在不做）
```

## 六、面试化：把项目变成 5 个故事

每个故事用 STAR 写（情境/任务/行动/结果），控制在 90 秒能讲完：

1. **架构决策**：为什么选 Express→NestJS？为什么不一开始就上微服务？
2. **性能优化**：N+1 或深分页或缓存，量化前后对比
3. **一致性/并发**：两人同时改同一数据怎么处理？消息重复怎么办？
4. **安全**：你发现并修复的越权或令牌问题
5. **交付与运维**：一次失败的部署/回滚，你怎么定位与恢复

**自检**：每个故事都能回答三层追问 —— "为什么这么做"、"不做会怎样"、"规模 ×10 会怎样"。

## 七、结业自评（全部打勾才算出师）

**能独立完成的事**

- [ ] 拿到一个模糊需求，能自己写出验收标准并实现
- [ ] 能设计数据库 schema 并解释每个索引的存在理由
- [ ] 能实现安全的认证授权，并说清威胁模型
- [ ] 能写出带测试、能部署、有监控的服务
- [ ] 能在无 AI 的情况下，2 小时内从零搭出一个可用的 API 骨架

**能讲清楚的概念**（能用大白话讲给同事听）

- [ ] 事件循环与非阻塞 IO
- [ ] JWT vs Session，以及为什么登出很麻烦
- [ ] 事务与隔离级别，以及丢失更新
- [ ] N+1 与索引最左前缀
- [ ] 缓存穿透/击穿/雪崩
- [ ] 至少一次投递与幂等
- [ ] 优雅关闭与滚动部署
- [ ] 12-Factor 与配置管理

**心态转变**（比技术更重要）

- [ ] 出问题第一反应是"看日志/看指标/复现"，而不是"问 AI 怎么办"
- [ ] 写代码前会先想"线上会怎么失败"
- [ ] 不再把"能跑"当作完成标准

## 八、下一步（结业后往哪走）

| 方向 | 需要补的 | 适合 |
| --- | --- | --- |
| 中大型业务后端 | 微服务、消息队列进阶（Kafka）、分布式事务、领域驱动 | 想进中大厂 |
| 全栈独立开发 | 支付接入、多租户、SaaS 计费、SEO、对象存储 | 想做产品/接单 |

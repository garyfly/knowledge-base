# S3 · 认证授权与安全（2 周）

> 目标：把"登录"这件事从"前端存个 token"升级为**你真的理解它在防谁**。
> 后端最容易被攻击的部分就是这一关，也是最容易在面试里被问穿的一关。

## 实战需求

在 `kb-api` 上加完整账号体系：

1. **注册 / 登录**：邮箱 + 密码；密码用 `argon2`（或 `bcrypt`）哈希，绝不存明文
2. **JWT 双令牌**：Access Token（15 分钟，内存/Header 携带）+ Refresh Token（7 天，HttpOnly Cookie 或独立存储）
3. **刷新与登出**：`POST /auth/refresh` 轮换 refresh token；`POST /auth/logout` 使其失效（服务端可撤销）
4. **数据隔离**：每个用户只能看到自己的笔记 —— 在 repository 层强制带 `userId`（不是靠 controller 记得传）
5. **RBAC**：角色 `user` / `admin`；`admin` 可查看用户列表、封禁用户；用中间件 `requireRole('admin')`
6. **限流**：登录接口 5 次/分钟/IP，全局 100 次/分钟/用户；用内存实现（S6 换 Redis）
7. **安全加固**：Helmet 类安全头、CORS 白名单、请求体大小限制、登录失败不区分"用户不存在/密码错"
8. **审计日志**：登录成功/失败、权限拒绝都落结构化日志

## 知识点与前端对照

| 知识点 | 前端视角 | 后端必须搞清楚 |
| --- | --- | --- |
| 密码存储 | 表单发给后端就完事 | 哈希 vs 加密、加盐、cost 因子、彩虹表、为什么用 argon2id |
| Session vs JWT | 习惯 localStorage 存 token | 有状态 vs 无状态、各自怎么"登出"、JWT 无法单方面作废的根本原因 |
| JWT 结构 | 一串不可读的字符串 | header.payload.signature、**payload 是 Base64 不是加密**、`exp/iat/aud/iss`、算法混淆攻击（`alg: none`） |
| 令牌存放 | localStorage 简单 | XSS 与 CSRF 的取舍：HttpOnly Cookie + SameSite vs Bearer Header |
| 认证 vs 授权 | 混为一谈 | 401（你是谁）vs 403（你能不能） |
| RBAC | 前端路由守卫 | 后端是唯一可信的权限点，前端守卫只是 UI |
| 越权 | 少见的概念 | **水平越权**（改 URL 看别人数据）比垂直越权更常见，必须测 |
| 限流 | 没见过 | 固定窗口 / 滑动窗口 / 令牌桶，怎么按 IP、按用户、按接口 |
| 安全头 | 无所谓 | CSP、HSTS、X-Content-Type-Options、Referrer-Policy |
| 时序攻击 | 没听过 | 比较密码/令牌要用恒定时间比较 |

## 验收标准

- [ ] 数据库（或内存 dump）里搜不到任何明文密码
- [ ] JWT payload 用 base64 解出来能看到内容 —— 并能解释这意味着什么
- [ ] 篡改 token 的 payload 后请求被拒；`alg: none` 攻击无效；过期 token 被拒
- [ ] 用户 A 的 token 无法读写用户 B 的笔记（有自动化测试证明）
- [ ] 普通用户调用 admin 接口返回 403 而不是 401 或 500
- [ ] 1 分钟内连续 6 次错误登录被限流（含 `Retry-After` 头）
- [ ] 登出后 refresh token 无法再用；旧 refresh 被重放会触发全端下线
- [ ] 能讲清楚：为什么 JWT 不能通过"服务端删除"来作废？你的方案怎么解决？
- [ ] 能讲清楚：为什么 token 存 localStorage 有风险？HttpOnly Cookie 又带来什么新问题？

## 常见坑

1. **把 JWT 当加密** —— payload 里放手机号、身份证 = 公开泄露。
2. **`jwt.verify` 不限制算法** —— 必须显式 `algorithms: ['HS256']`，且密钥足够长。
3. **只在 controller 加权限判断** —— 漏一个接口就出事，要在 repository/中间件层做"默认安全"。
4. **refresh token 存成明文无过期** —— 必须可撤销、有 TTL、轮换。
5. **登录错误信息区分"用户不存在/密码错"** —— 直接给攻击者用户名枚举能力。
6. **限流只按 IP** —— NAT 后面一堆人共享 IP；只按用户则注册接口无效。
7. **CORS 写成 `origin: true` + credentials** —— 等于允许任何站点带 cookie 打你。
8. **`bcrypt` cost 设太高** —— 登录接口变成 DoS 入口，要用基准测试定参数。

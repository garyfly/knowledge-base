# S7 · 测试与架构升级（2 周）

> 目标：① 让你的代码"改得动"（测试覆盖）；② 用 NestJS 重写核心模块，理解**企业级后端为什么要分层与依赖注入**。
> 前端转后端最常见的短板就是这两个：不会写测试、不懂架构分层。

## 实战需求

**第 1 周：测试**

1. **测试金字塔落地**：
   - 单元测试：service 层纯逻辑（用假 repository，不碰数据库）
   - 集成测试：repository + 真实测试数据库（每次跑用独立 schema 或事务回滚）
   - 接口测试：Supertest 覆盖 HTTP 层（含鉴权、校验、错误结构）
2. **覆盖率**：核心模块行覆盖 ≥ 70%，并**明确排除**不需要测的文件（config、类型）
3. **测试质量**：禁止"只测 happy path"；每个模块至少覆盖边界与错误分支
4. **测试基础设施**：
   - 测试数据库自动准备与清理（`docker compose` + 每套测试独立库）
   - 工厂函数造数据（`makeUser()` / `makeNote()`），避免测试之间互相依赖
   - 冻结时间（防 flaky）、随机 id 可注入
5. **CI 里跑测试**：GitHub Actions 上跑 lint + typecheck + test（先只跑，不讲部署）

**第 2 周：NestJS 重写**

用 NestJS 重写 `auth` + `notes` 两个模块（数据层继续用 Prisma），要求：

- Module / Controller / Provider / Guard / Interceptor / Pipe / ExceptionFilter 全部用上
- DTO + `class-validator`（或继续用 Zod，但要说明取舍）
- 全局异常过滤器输出和 Express 版**完全一致**的错误结构
- `ConfigModule` 管理配置并做启动校验
- `PrismaService` 生命周期钩子（`onModuleInit` / `onModuleDestroy`）
- 写一份《Express 版 vs NestJS 版对照表》：同一需求两种写法，各自优劣
- 关键请求路径加自定义 Interceptor：统一响应包装 + 耗时日志

## 知识点与前端对照

| 知识点 | 前端视角 | 后端本周要掌握 |
| --- | --- | --- |
| 单元测试 | Vitest 测组件 | 纯函数式 service 更好测；依赖注入让 mock 变简单 |
| 集成测试 | 没有 | 数据库状态污染、事务回滚、测试隔离 |
| Mock | `vi.mock` | 用接口注入替身优于模块级 mock；避免 mock 被测逻辑本身 |
| 覆盖率 | 数字游戏 | 覆盖率不等于质量，重点是分支覆盖与"关键路径必测" |
| 依赖注入 | React Context | IoC 容器、生命周期作用域（单例/请求级）、构造注入 |
| 装饰器 | 少见 | TS 装饰器（Nest 依赖 `emitDecoratorMetadata`） |
| 管道/守卫/拦截器 | axios 拦截器 | 请求处理链上各层职责：校验 / 鉴权 / 横切逻辑 |
| 模块化 | 组件目录 | 按领域划分模块、模块间依赖显式声明、避免循环依赖 |
| 分层职责 | 见 S2 | 领域边界、DTO 与实体的转换、服务编排 |
| 集成/E2E | 手点 | 一条命令跑全链路验证 |

## 常见坑

1. **测试互相污染** —— 共用一个库且不清理，第二个测试随机失败（flaky 的根源）。
2. **过度 mock** —— 把 repository 全 mock 掉，测试全绿但线上全崩；关键路径要真库。
3. **测实现细节** —— 断言内部函数被调用几次，重构就红；应断言行为与结果。
4. **`process.env` 在测试里被真实读取** —— 测试配置必须显式注入。
5. **时间相关断言** —— `new Date()` 导致跨天/时区失败，用可控时钟。
6. **Nest 忘记 `emitDecoratorMetadata` / `experimentalDecorators`** —— 依赖注入直接报"无法解析参数"。
7. **Nest 默认返回结构与 Express 版不一致** —— 需要全局 Interceptor 包裹，别让两套 API 行为分裂。
8. **循环依赖** —— 模块互相 import，用 `forwardRef` 是遮掩，优先重新划边界。
9. **`onModuleDestroy` 里不关连接池** —— E2E 测试跑完进程不退出（Jest/Vitest 挂住）。

## AI 协作提示词

**测试教练（核心用法：让它出题，你写测试）：**
```text
这是我的 notes service 代码（贴代码）。
请列出 8 个必须覆盖的测试用例名（含边界与错误分支），按优先级排序。
只给用例名和"预期行为一句话"，不要给测试实现。我写完发你批改。
```

**测试审查：**
```text
这是我写的测试（贴代码）。请指出 3 个"看起来在测，实际测不到东西"的问题
（比如断言太弱、mock 掉了被测逻辑、依赖执行顺序），每条说明为什么危险。
```

**NestJS 迁移顾问（别让它代写整个模块）：**
```text
这是我的 Express controller 和中间件（贴代码）。
请给出迁移到 NestJS 的"结构映射表"（每个文件 → Nest 里的什么角色），
并指出其中 2 处迁移后行为容易变化的地方（尤其错误处理与校验）。不要给 Nest 完整代码。
```

**架构对话（苏格拉底式）：**
```text
用提问方式帮我判断：我这个项目是否"过度分层"了？
先问我 3 个问题（比如团队规模、变更频率、部署方式），根据我的回答再给结论和理由。
```

**面试官模式：**
```text
围绕"测试策略 + 分层架构 + NestJS 机制"出 6 道题，一次一题。
我答完后你要追问一层（"如果并发 1000 呢""如果团队 5 个人呢"）。不要提前给答案。
```

# AI 提示词库 · Node.js 后端学习

> 用法：复制 → 替换 `<>` 内容 → 发送。所有提示词都遵循同一个原则：**AI 当讲师/审查者/陪练，不当代写器。**

## 通用原则（贴在显示器边上）

| 想要的效果 | 提示词里必须包含 |
| --- | --- |
| 让它出题考我 | 「一次一道」「我答完再给下一道」「答错先给提示不要给答案」「不要提前总结」 |
| 让它审查我的代码 | 「只做审查，不要重写」「不要给完整实现」「每条格式：问题/触发场景/修复方向」 |
| 让它解释概念 | 「用前端已熟悉的概念类比」「一句话类比 + 一句话在 Node 里具体指什么」 |
| 让它讲故障 | 「给出可执行的验证命令或日志关键词」「按可能性排序」 |
| 防止它编 API | 「标注每个 API 的所属版本，若不确定就说不确定」+ 自己去官方文档核对 |

## 1. 学习启动 / 计划类

**① 制定本周计划**
```text
我是前端，正在学 Node 后端，本周进入 <阶段名>（我的阶段目标：<一句话>）。
我每周可投入 <X> 小时，工作日 <Y> 分钟，周末 <Z> 小时。
请把这周拆成 7 天的具体任务，每天不超过 3 件事，每件事都要有"可运行/可验证"的产出。
不要给学习资料清单，只要任务。最后告诉我："如果只有 3 天时间，优先做哪 3 件"。
```

**② 卡住了，先要提示不要答案**
```text
我在做 <需求>，卡在 <具体现象：报错/行为不符/不知从哪下手>。
我的代码是（贴最小相关代码），我已经试过 <尝试>，我的猜测是 <猜测>。
请只给我一个提示（不超过 3 句话），让我自己继续试；不要给代码。
```

**③ 判断我是不是真懂**
```text
我来解释 <概念>：（我的解释）
请指出其中不准确、含糊或"只记住了结论不理解原因"的地方，然后追问我 3 个由浅入深的问题验证。
不要给我标准答案，先听我答。
```

**④ 概念类比（前端视角）**
```text
用"我已经熟悉的前端概念"解释 <后端概念>。
格式：① 一句话类比 ② 在 Node 里具体指什么 ③ 一个真实事故场景 ④ 我容易搞错的 1 个点。
```

## 2. 代码审查 / 设计评审类

**⑤ 严格但克制的 Reviewer**
```text
下面是我的 <文件名/函数>（贴代码）。
请扮演严格的后端 reviewer，只挑"会导致线上 bug、安全事故或维护灾难"的问题，最多 5 条。
每条格式：问题 / 触发场景（具体到请求或并发时序）/ 修复方向（一句话）。
不要重写代码，不要提风格问题。
```

**⑥ 架构扩散性评审**
```text
这是我的目录结构与分层依赖（贴 tree + 关键 import）。
假设：① 三个月后要换数据库 ② 六个月内团队从 1 人变 5 人。
请指出我的架构里哪些地方会造成"改动扩散"，最多 3 条，每条给出最小改法。
```

**⑦ 三层追问（防止自己被表面说服）**
```text
我打算这样做：<方案>，理由是 <理由>。
请扮演持怀疑态度的资深工程师，追问三层：
① 为什么这么做？② 不做会怎样？③ 如果流量/数据量 ×10 会怎样？
一次问一层，等我回答后再问下一层。
```

**⑧ 找"没写的代码"（边界与异常）**
```text
这是我的 <接口/函数> 实现（贴代码）。
请只列"我没有处理的情况"，按发生概率排序，最多 8 条，每条给一行失败后果。
不给修复代码。
```

## 3. 出题 / 陪练 / 面试类（最高价值用法）

**⑨ 面试官模式（通用）**
```text
你是后端面试官。主题：<认证/数据库/性能/架构>。
规则：出 6 道题，由浅入深，最后一题是开放场景题；一次只问一题；我答完你点评并追问一层；
答错时不要直接给答案，先给一个提示；不要提前总结或给答案清单。
```

**⑩ 代码审查出题（基于我自己的代码）**
```text
基于我这几周的代码（贴关键文件），出 5 道代码审查题：
每题给一段有缺陷的代码（可以基于我的代码改造），让我指出问题。
一次一道，我答完给评分与解析。
```

**⑪ 故障演练**
```text
假设我上线的服务出现以下现象：<现象>。
请给出 5 个可能根因（按概率排序），每个附 2 条具体的验证命令或日志关键词。
不要给修复代码，我要自己查。
```

**⑫ 性能瓶颈陪练**
```text
这是我的压测结果（贴 autocannon/k6 输出）、机器配置和关键接口代码。
请像性能工程师一样：列出 4 个候选瓶颈、每个的验证方法（具体命令/日志关键词），
告诉我第一个该查什么。不要直接给优化后的代码。
```

**⑬ 压力提问（追问规模）**
```text
针对我的设计 <描述>，请连续追问：
① 100 个用户时的问题？② 1 万用户时的问题？③ 数据量到 1000 万行时的问题？
每次只问一个，等我回答并给出数据/理由后再深入。
```

## 4. 排障 / 学习复盘类

**⑭ 报错讲解（先自我分析再问）**
```text
我遇到这个错误：（贴完整错误栈）
我的环境：Node <版本>，<框架> <版本>，<数据库> <版本>。
我自己分析：<你的判断>。
请：① 指出我的分析对不对 ② 讲清这个错误的机制（为什么会发生）
③ 给我 3 步排查顺序 ④ 告诉我怎么预防。不要直接给"改成这样"。
```

**⑮ 每周复盘引导**
```text
这周我学了 <内容>，写了这些代码（贴关键片段或描述），踩了这些坑（贴我的记录）。
请用提问方式帮我复盘：先问我 5 个问题（每个都要逼我给出具体证据而不是"感觉学会了"），
我答完后你指出我可能高估自己的地方。
```

**⑯ 教 AI 学（费曼技巧）**
```text
我要用费曼技巧检验理解。我现在把 <主题> 讲给"完全不懂后端的实习生"听：
<我的讲解>
请扮演那个实习生，提出 3 个"听不懂/追问细节"的问题，并指出我讲解里跳过的关键前提。
```

## 5. 阶段性资产类

**⑰ 生成技术文档骨架（不代写内容）**
```text
我要为项目 <名称> 写 <README/技术复盘/性能报告>。
请给出这些文档的章节骨架与每节"应该写什么、读者关心什么"的提示，
不要替我写内容，我自己填。
```

**⑱ 提炼面试故事**
```text
这是我的项目经历（贴复盘文档）。
请帮我提炼 5 个 STAR 结构的技术故事（架构决策/性能优化/并发一致性/安全/部署运维），
每个给我"标题 + 情境一句话 + 需要我补充的数据项"。
不要替我编造数字，缺数据的地方要标注"待补"。
```

**⑲ 简历表述打磨**
```text
这是我的项目描述（贴原文）。
请指出：① 哪些是"没有信息量的形容"② 哪些数字缺失 ③ 面试官会因此追问什么。
给出改写方向（不要替我写最终版）。
```

## 6. 反模式清单（这些提示词不要发）

| ❌ 不要这样问 | ✅ 改成 |
| --- | --- |
| "帮我写一个用户注册登录模块" | "我要实现注册登录，我的方案是 X，请指出其中的安全漏洞" |
| "这段代码报错，帮我修" | "错误是 X，我分析原因是 Y，请验证我的分析并给排查顺序" |
| "给我一个完整项目" | "给我这个阶段的需求和验收标准，我自己实现" |
| "总结一下 Express 怎么用" | "我写了这个中间件，请审查它和 Express 行为不一致的地方" |
| "怎么优化这个接口" | "这是压测数据，列出候选瓶颈和验证方法" |
| "写一下测试" | "列出必须覆盖的 8 个用例名，我写实现" |

## 7. 每日 30 秒自检（贴在笔记顶部）

- [ ] 今天我**自己写**的代码量 > AI 给我的代码量 × 5？
- [ ] 今天学到的每个 API，我都去**官方文档**确认过版本与签名？
- [ ] 我今天遇到的 bug，我能说出**根因**而不只是"改好了"？
- [ ] 今天有任何一个问题，是**我先想 10 分钟**才问 AI 的？
- [ ] 我今天的产出是**能跑的东西**，不是"看完了一篇文章"？

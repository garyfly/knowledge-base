## 0. 先把这题拆成 5 个函数，再动手

D2 看着是 3 个功能，其实是一条流水线 + 一个纯函数：

```
① resolveInput(用户传的路径)   → 绝对路径
② walk(dir)                    → string[]   （所有 .md 的绝对路径）
③ readAndCount(file)           → { path, chars, bytes }
④ aggregate(结果数组)          → { fileCount, totalChars, totalBytes, perFile[] }
⑤ renderTable(perFile)         → string     （纯格式化，不碰 fs）
```

| 拆分 | 收益 |
| --- | --- |
| ② 只返回路径列表，不顺便统计 | 可以先打印路径数对拍，再往下做 |
| ③ 是 IO + 纯函数，④⑤ 是纯计算 | **纯函数可以在 REPL/tmp 脚本里直接喂字符串测边界**，这是 D2 最快的调试方式 |
| ⑤ 只吃数据不碰 fs | D3 的 `--json` 就是同一个数组换个 renderer，逻辑零改动 |
| ③ 的读取实现被隔离 | D5 换成流式读，只动 ③ 内部，其它不动 |

建议文件布局（`rootDir: src`，ESM 相对导入必须写 `.js`）：

```
src/index.ts            # 只做 argv 分发（D3 也在这加）
src/walk.ts             # ② 递归遍历
src/count.ts            # countChars 纯函数（不要 import fs！）
src/report.ts           # ④⑤ 聚合与渲染
```

> [!tip] 分层的分水岭
> 判断有没有分对层：**`renderTable` 里不该有 `console.log`**，它接数据、返回字符串。
> `countChars` 里不该出现 `fs`。做到了，D3 和 D5 都会很顺。

## 1. 功能一：递归遍历

### 1.1 `readdir(dir, { withFileTypes: true })` 给了你什么

```ts
const entries = await fs.readdir(dir, { withFileTypes: true }); // Dirent[]
```

- **不写这个选项** → 返回 `string[]`（只有文件名），想知道是不是目录还得再 `stat` 一次。
- **写了** → 返回 `Dirent[]`，自带 `isDirectory()` / `isFile()` / `isSymbolicLink()` 和 `.name`。
- 后端视角的意义：不然要对每个条目多发一次 `stat` 系统调用，而且两次调用之间文件可能已经变了（经典 **TOCTOU**）。`readdir` 在**一次**系统调用里就把类型带回来了。
- **坑**：`d.name` 只是 **basename**，不是路径。必须 `path.join(dir, d.name)` 拼回去。拿着 `d.name` 去 `readFile` 只在 cwd 命中——新手最典型的一行 bug。

### 1.2 `join` / `resolve` / 字符串拼接

| 表达式（Node v24 实测） | 结果 | 要点 |
| --- | --- | --- |
| `path.join('a/', '/b')` | `"a\\b"` | 自动处理多余斜杠，Windows 用 `\` |
| `path.resolve('a/../b')` | `"E:\\...\\nb-cli\\b"` | **相对 → 绝对**，靠 `process.cwd()` 兜底 |
| `path.join('a', '..', 'b')` | `"b"` | 只规范化，不转绝对 |
| `path.extname('.gitignore')` | `""` | 前导点不算扩展名（符合直觉，不会误判） |
| `path.extname('a.MD')` | `".MD"` | **大小写敏感** |

- **不要用 `dir + '/' + name`**：Windows 分隔符、`C:` 开头、UNC 路径、结尾斜杠、`..` 都能让你翻车。
- **`resolve` 与 `join` 的分工**：入口处 `resolve` 一次，内部全程 `join`。
  ```ts
  const root = path.resolve(userInput);   // 只在这里做一次
  // 递归里一律 path.join(root, name) 往下传
  ```
  这正是"相对路径基于 `process.cwd()` 而非脚本位置"那条坑的解法。
- 输出 Top10 时用 `path.relative(root, file)` 算回相对路径，表格好看且不受 cwd 影响。
- **`.md` 判断**：`path.extname(name).toLowerCase() === '.md'` 比 `endsWith` 稳（`notes.md.bak` 不会误判）。

### 1.3 递归怎么写

```ts
async function walk(dir: string): Promise<string[]>   // 返回所有 .md 绝对路径
```

- 深度优先，`for (const d of entries)` 逐个处理，遇目录就 `await walk(child)`。
- **今天串行是对的**：正确性优先。等 D4 写完 `runWithConcurrency` 再回来**并发化"读文件"那一步**（IO 密集），递归本身没必要并发。先留钩子。
- 显式栈版本（不用递归）能避免超深目录爆栈；md 仓库用不上，但面试会问，知道有这回事。

### 1.4 跳过规则：想清楚是"通用规则"还是"白名单"

需求列了 `.obsidian` / `node_modules` / `.` 开头目录。但注意：**`.obsidian`、`.git`、`.copilot` 已经被"`.` 开头"这条通用规则覆盖了**。

```ts
const SKIP_DIRS = new Set(['node_modules']);   // 特例
// d.isDirectory() && (d.name.startsWith('.') || SKIP_DIRS.has(d.name))
```

三个必须想清楚的边界：

1. **只跳目录，不跳文件**。不加 `isDirectory()`，`.gitignore` 这种文件也会被跳掉。
2. **入口目录本身叫 `.foo` 怎么办？** 跳过只作用于"子项"，入口是你传进来的，不该被跳。语义差别要想清楚。
3. **符号链接 / Windows junction**：`isSymbolicLink()` 指向父目录会**无限递归**。最省事：不跟随软链接（`isDirectory()` 对链接返回 false，天然跳过），或用 `fs.realpath` 去重。

### 1.5 文件数 / 字符数 / 字节数怎么拿最省

**一次读取同时拿字节和文本：**

```ts
const buf = await fs.readFile(filePath);   // Buffer，不写编码
const bytes = buf.length;                  // 磁盘真实字节数
const text  = buf.toString('utf8');
```

- `readFile(p, 'utf8')` 直接给字符串，`buf.length` 就没了，还得再 `stat` 一次 → 又有两次调用之间的不一致。
- 实测：含 BOM 的文件，`stat().size`、`buf.length`、`Buffer.byteLength(text, 'utf8')` 三者相等。
- **字节数用 `buf.length` 最直接**，语义 = 文件实际大小（含 BOM）。

**错误处理**：单文件读失败（权限、刚被删）不该让整次统计挂掉。

```ts
type Fail = { path: string; reason: string };
// walk 与读文件各自 try/catch，塞进 failures[]，最后打印 "N 个文件读取失败"
```

`readdir` 也可能抛（权限）。⚠️ **递归里的 try/catch 只包当前层，别在 catch 里 `return`，否则会静默吞掉整个兄弟目录。**

## 2. 功能二：`countChars(text)`

### 2.1 先拍板口径（这步不能跳）

需求：**CJK 字符各算 1 个 + 连续的字母数字整体算 1 个"单词"**，即 Word 的"字数"口径。以下必须自己决定并写进注释：

- [ ] 中文标点 `。，、""` 算不算"字"？
- [ ] `_` 算不算字母数字？（决定 `a_b` 是 1 个词还是 2 个）
- [ ] 全角数字 `１２３`（`\uFF10-\uFF19`）算不算？
- [ ] frontmatter（`---\ntitle: x\n---`）算不算？（建议算，但要说明这是决策）
- [ ] 代码块里的 `const a = 1` 算不算？（建议算；要排除是另一个功能）

### 2.2 为什么不能用 `.length`

| 表达式（实测） | 结果 |
| --- | --- |
| `'中'.length` | `1` |
| `'😀'.length` | **`2`** |
| `[...'😀'].length` | `1` |

- JS 字符串是 **UTF-16**，`.length` 数的是 **code unit（码元）**，不是"人眼看到的字符"。
- 中文基本平面内 1 字 = 1 码元，所以中文上 `length` 碰巧对；emoji、生僻字（如 𠮷）是**代理对**，占 2 个码元。
- 按码点数：`[...text]` / `Array.from(text)` / `for...of`，或正则加 `u` 标志（`u` 让 `.` 匹配一个码点）。
- 码点也不是终点：`é` 可能是 `e` + 组合符 U+0301（2 码点 1 字位）。精确要用 `Intl.Segmenter`——**知道就行，现在别上**。

### 2.3 CJK 范围（理解每一段，别背乱码）

```
\u4E00-\u9FFF   CJK 统一表意文字（最常用，99% 的汉字）
\u3400-\u4DBF   CJK 扩展 A（生僻字）
\uF900-\uFAFF   CJK 兼容表意文字
\u3000-\u303F   CJK 标点（。、《》…）—— 是否纳入由你拍板
\u3040-\u30FF   日文假名
\uAC00-\uD7AF   韩文谚文
```

**路 A：手写码点范围**（先写这个，可解释性最强）

```ts
const CJK  = /[\u4E00-\u9FFF\u3400-\u4DBF]/;
const WORD = /[A-Za-z0-9]+/;
```

**路 B：Unicode 属性转义**（现代 Node 更准，需 `u` 标志）

```ts
/\p{Script=Han}/gu      // 实测 '中文abcの한' → ['中','文']
```

`Script=Han` 覆盖所有扩展区，比老教程的 `\u4E00-\u9FA5`（**漏字**）准得多；但它**不含**假名和韩文——中文场景正好是你要的。建议：先 A 跑通，再用 B 对拍看差多少，差异处想清原因。这个"对拍"动作本身就是学习。

### 2.4 带 `g` 的正则是**有状态**的（本题最阴的坑）

```js
const re = /[A-Za-z]+/g;
re.exec('abc def')   // lastIndex → 3
re.test('abc def')   // 从上次位置继续找 → lastIndex → 7   ← 结果受调用历史影响
```

`g` 正则对象带 `lastIndex`，`exec`/`test` 会推进它。`countChars` 会被调用几百次（每文件一次），如果正则定义在**模块顶层**又在函数里用 `exec`/`test` 循环，**上一次调用的残留位置会污染下一次** → "同一个文件跑两遍结果不一样"。

三条防身规则：

1. 正则写在**函数内部**（每次新建，最省心）；或
2. 每次用前 `re.lastIndex = 0`；
3. 用 `str.match(re)`（带 `g` 返回全部匹配，会自己收尾）或 `text.matchAll(re)`。

> [!warning] 别混用
> `matchAll` / `match` 与 `exec` 不要共用同一个正则对象。另外 `matchAll` **必须**带 `g`，否则抛错。

### 2.5 两种计数策略

**策略一：正则扫描 + 求和**（先写这个，短）

```
cjk   = text.match(CJK_G)?.length  ?? 0    // 逐字匹配（无 +）
words = text.match(WORD_G)?.length ?? 0    // 连续算一个（有 +）
return cjk + words
```

- `CJK_G = /[\u4E00-\u9FFF\u3400-\u4DBF]/g`（**没有 `+`**）
- `WORD_G = /[A-Za-z0-9]+/g`（**有 `+`**）
- `?.length ?? 0` 处理无匹配（`match` 返回 `null`）。
- 实测：`'a_b'.match(/[A-Za-z0-9]+/g)` → `['a','b']`，而 `/\b\w+\b/g` → `['a_b']`。**`\w` 含下划线，`[A-Za-z0-9]` 不含**——这就是要拍板的那条。

**策略二：单次遍历状态机**（更准更快更好解释）

```
inWord = false
for (const ch of text) {                  // for...of 按码点
  if (isCJK(ch))           { count++; inWord = false }
  else if (isWordChar(ch)) { if (!inWord) { count++; inWord = true } }
  else                     { inWord = false }
}
```

`中文abc` 自然得到 3，且没有正则状态问题。⚠️ 若用 `CJK_RE.test(ch)` 判断，**别给这个正则加 `g`**（又会踩 2.4）。两种都自己写一遍再对比，是最好的练习。

### 2.6 BOM 到底会错在哪（要理解，别背结论）

- UTF-8 BOM = 字节 `EF BB BF` = 字符 `U+FEFF`，记事本/部分编辑器会写。
- 实测：`fs.readFile(p, 'utf8')` **不会**替你去掉它，`text.charCodeAt(0)` 就是 `65279`。
- 对本题的**真实影响**（很多人讲错）：
  - 统计正则**不带 `^`** 时，BOM 既不是 CJK 也不是字母数字，**其实不影响计数**（实测 `'\uFEFFabc'.match(/[A-Za-z]+/g)` → `['abc']` ✅）。
  - 真正会错的是**锚点场景**：实测 `'\uFEFF# t'.match(/^#/m)` → `null`。即"首行是不是 frontmatter / 标题"这类逻辑整体失配。
  - 所以准确说法是：**BOM 会污染所有依赖"开头 / 行首"的逻辑**，也让 `text[0] === '#'` 失灵。
- **正确姿势：入口统一清理一次。**
  ```ts
  text = text.replace(/^\uFEFF/, '');   // 或 charCodeAt(0) === 0xFEFF → slice(1)
  ```
  放在"读到文本之后、任何解析之前"，全项目只做一次。
- 附加：`'\uFEFFabc'.trim()` 实测 → `'abc'`（ES2015+ 把 `\uFEFF` 当空白）。能顺手去掉，但**别依赖它**——你要的是"只去 BOM"，不是"去所有空白"。
- **字节数扣不扣 BOM？** 建议不扣（`buf.length` = 文件真实大小）。决策写进注释。

### 2.7 边界用例清单（照着写测试，比读十篇文章有用）

| 输入 | 期望 | 为什么 |
| --- | --- | --- |
| `''` | 0 | 空文件（你库里肯定有） |
| `'hello world'` | 2 | 分隔符断词 |
| `'中文abc'` | 3 | 中英混排边界 |
| `'a_b'` | 1 或 2 | 取决于 `_` 的定义 |
| `'１２３'` | 0 或 1 | 全角数字，`[0-9]` 实测不匹配（`null`） |
| `'\uFEFF中文'` | 2 | BOM 不计数 |
| `'😀'` | 0 | emoji 非 CJK 非字母 |
| `'---\ntitle: x\n---'` | ? | frontmatter 口径 |
| `'中文' + 'a'.repeat(1e6)` | 3 | 超长单行；正则无嵌套量词，不会灾难性回溯 |

> [!tip] 测 `countChars` 根本不需要 fs
> 写个 `if (countChars('中文abc') !== 3) throw new Error(...)` 的小脚本用 tsx 跑即可。
> 这就是把纯函数拆出来的全部意义。

## 3. 功能三：Top10 表格

### 3.1 `sort` 的三个坑

```ts
perFile.sort((a, b) => b.chars - a.chars);
```

1. **默认按字符串比较**：实测 `[10,9,100].sort()` → `[10,100,9]`。**必须传 comparator**。
2. **`sort()` 原地修改**（mutating）。后面还要用原始顺序就先 `[...arr].sort()`，或用 Node 20+ 的 `toSorted()`。
3. **稳定性与"结果不稳定"**：ES2019 起 `sort` 保证稳定，字数相同的文件保持"输入顺序"——而 `readdir` 顺序**不保证**（不同文件系统/机器可能不同）。要可复现就加二级键：
   ```ts
   .sort((a, b) => b.chars - a.chars || a.path.localeCompare(b.path))
   ```

取前 10 用 `slice(0, 10)`。**别用 `splice`**（会改原数组，在 `for` 里用还会漏元素）。
要不要"部分排序"只找 top10？文件几百个全排完全够，**别过早优化**。

### 3.2 `padStart` 与"中文宽度"这个真坑

```ts
String(n).padStart(width, ' ')   // 数字右对齐
name.padEnd(width, ' ')          // 文本左对齐
```

**坑：`padStart` 按 code unit 数补齐，而中文在终端占 2 列。** 实测效果：

```
中文文件名.md |   1234
    a.md |      7
```

`中文文件名.md` 是 8 码元但占 16 列，`a.md` 是 4 码元占 4 列 → 竖线完全对不齐。三条出路：

1. **最简单**：文件名放**最后一列**，中文只影响行尾，竖线天然对齐。
2. **认真做**：写 `displayWidth(str)`，CJK/全角算 2、ASCII 算 1，用它算列宽与补空格（进阶可用 `Intl.Segmenter` + East Asian Width）。
3. **偷懒**：`console.table(rows)` 一把梭——但控制力弱、不好接 `--json`。

**列宽计算的真坑：**

```ts
const w = Math.max(...rows.map(r => r.name.length));   // rows 为空 → -Infinity（实测）
```

空目录时 `Math.max()` 返回 `-Infinity`，`padStart(-Infinity)` 直接抛错。用 `reduce(..., 0)` 或先判 `rows.length === 0`。**空数组是所有聚合函数的第一号边界。**

数字列同理：别硬编 `padStart(6)`，用最大数字宽度算出来，否则百万字的文件会撑破表格。

### 3.3 表格 = 列宽 + 每行拼接

```
1. 每行转成 [name, chars, bytes] 的字符串数组
2. 逐列求最大显示宽度（空数组 → 0）
3. 每行按列宽 pad（文本 padEnd、数字 padStart）+ 分隔符 join
4. 可选：表头 + 分隔线 + 总计行
```

- 千分位用 `(1234567).toLocaleString('en-US')` 或 `Intl.NumberFormat`，别手写。
- `console.log` 就够；要精确控制换行可用 `process.stdout.write`（不自动加 `\n`）。
- **`renderTable` 接数据、返回字符串**，D3 才能拿同一份数据渲染 JSON。

### 3.4 汇总数字的边界

- 平均字数 = `totalChars / fileCount`，**`fileCount === 0` 时是 `NaN`**，要显式处理。
- 需求只要"文件数 / 总字符数 / 总字节数"。平均是加分项，加之前先决定空文件算不算进分母——即"空文件把平均值拉偏"那条。

## 4. 实现顺序（每步都能单独验证）

1. **`countChars` + 手写用例**（完全不碰 fs）——把 2.7 那张表跑通，今天最该先做的。
2. **`walk`，只打印路径列表**——先不管计数，对拍"找到的文件数"。
3. **接上读取和计数**——打印每文件 `chars/bytes`，挑 1 个文件用编辑器字数对拍（误差要能解释）。
4. **`aggregate` + 表格渲染**——最后再美化输出。

**对拍脚本（PowerShell）：**

```powershell
(Get-ChildItem -Recurse -File -Filter *.md |
  Where-Object { $_.FullName -notmatch '\\\.' }).Count
```

> [!note] 对拍结果不一致 ≠ 一定是 bug
> 这条 PowerShell 与你的 JS 跳过规则不一定完全等价。**差异要能解释**，别一看到数字不同就改代码。

**三个验证习惯：**

- 先 `console.log` 中间结果，别一上来就调格式；
- 绝对路径测一次、相对路径再测一次（验证 `resolve` 放的位置对不对）；
- 跑完 `git status` 确认只读没写（`count` 就该是只读操作）。

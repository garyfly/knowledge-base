# Qwen3.8-Flash-Next 与「6GB 显存 + 32GB 内存 + 188GB 空闲盘」可行性侦察笔记

- 侦察时间：2026-11-08
- 目标机器：RTX 3060 Laptop 6GB / i7-11800H / 32GB DDR4 / Win11 / 单盘最大空闲 **188.6GB**
- 网络事实：huggingface.co 直连超时；**hf-mirror.com 可用**（本笔记所有 HF 事实均取自 hf-mirror API）；ollama.com / modelscope.cn / GitHub API / unsloth.ai / help.aliyun.com 均可达；知乎正文 403（只有搜索摘要）。
- 标注约定：**【实测】**=有第三方测量数据；**【官方】**=厂商/框架文档；**【推算】**=按体积/架构推的估算，未实测。

---

## 0. TL;DR（先看这 6 条）

1. **Qwen3.8-Flash-Next 的 BF16 官方权重 = 360,023,343,554 字节（335.3 GiB / 360.0 GB），131 个 safetensors 分片**，单这一项就超过 188.6GB 的空闲盘，**airllm 路线在这台机器上第一步（下载）就物理不成立**。FP8 版 185.56GB（172.8 GiB）也超盘。
2. airllm README 明说该模型需要 **~360GB checkpoint 磁盘**、**64GB 内存**；而 airllm 切分还会再占一份盘（`check_space` 按模型原大小预留，见 issue #309）。用户的 188GB / 32GB 两个硬条件都不满足。
3. **airllm 在 Windows 上有真实的「慢到不可用」证据**：issue #364（Win11 + RTX 5060 Ti，airllm 4.0.0）跑 **3B 模型 = 28.6 秒/token**；issue #396 同平台 3B 形状模型 stock 20.0 秒/token。官方 README 没有任何 Windows 支持声明（只有 MacOS 章节）。
4. **2026 年真正把 Flash-Next 跑快的是 Strata（MIT，Niko1221/Strata），不是 airllm**，但它的实测起点是 **12GB 显存 + 48~64GB 内存**：RTX 3060 12GB + 64GB RAM 在 Windows 11 上 Q2_0 解码 **45.3 tok/s**（128 token 上下文）、260K 上下文仍有 **37.4 tok/s**【实测】。6GB 显存 + 32GB 内存不在任何已发布配置之内。
5. 这台机器上**唯一体积可行的 Flash-Next 路线是 GGUF 2bit**：ISTA-DASLab Q2_0 **61.9 GiB（下载 ≈66.5GB）**、unsloth UD-IQ1_S **61.8 GiB**，都能塞进 188GB；但 32GB 内存 + 6GB 显存低于 Strata 文档的 low-RAM 门槛（文档写「32GB PC + 12~16GB GPU 才跑 Coder 版」），只能 SSD 流式，**速度无任何实测数据**。
6. **结论：Flash-Next 在这台机器上不要本地跑**。保住现有 Ollama 基线（LFM2.5 8B-A1B 83 tok/s、Qwen3.6 35B-A3B 29 tok/s），需要 Flash-Next 级能力就调 **Qwen3.8-Flash 云 API：输入 $0.16 / 输出 $0.47 每百万 token、100 万上下文**（比本地推理电费+等待都便宜）。

### 3.2 airllm 真实第三方/社区证据（全部 GitHub issue，可核查）

**→ 「找不到 Flash-Next 在 6GB / 32GB / Windows 上的第三方实测」。** 只有 airllm 自己的 PR #353 一句话（4090 上 5.95GB、生成一句正确的话、无 tok/s、无 Windows、无首字延迟）。第三方转载（如 pikabu 2026-09-09 的俄文帖）也只是复述 airllm 数据。

### 3.3 用数字推 airllm 在这台机器上的下场【推算】

- Flash-Next BF16 每 token 需从磁盘读完整 48 层（≈360GB）。NVMe 顺序读按 3GB/s 算 → **≈120 秒/token 的 I/O 下限**；即便按最乐观 7GB/s 也是 ≈51 秒/token。
- 32GB 内存装不下 360GB，OS page cache 帮不上；PLE 表 100GB（BF16）mmap 随机查表更雪上加霜（airllm 自己也要求 64GB 内存）。
- 对比用户基线：LFM2.5 8B-A1B **83 tok/s**、Qwen3.6 35B-A3B **29 tok/s**。airllm 跑 Flash-Next 大概率是 **0.01~0.02 tok/s（≈1~2 分钟/token）**，比基线慢 3~4 个数量级。
- 且前置条件根本不成立：**磁盘要 360GB+，只有 188.6GB**。

## 4. 真实第三方跑分（Qwen3.8-Flash-Next，非 airllm）

### 4.1 Strata（当前跑 Flash-Next 最现实的本地 runtime，MIT）

来源：`https://github.com/Niko1221/Strata`（HN 940 分帖「Run Qwen 3.8 Flash Next (125B) on consumer hardware (RTX 4090) at 100T/s」指向它）；数据文件：`docs/MODELS.md`、`bench/results/...`
关键机制：专家分片 1 进 RAM，其余进显卡；**29GB n-gram 查表分片留在 SSD**；模型要求 **RAM ≥ 专家 + 约 10GB**。

|---|---|---|---:|---:|---|

| 同上 | Q2_0 | 4K | 42.9 | 882.3 | 同上 |

→ **6GB 显卡比它文档里最低的 12GB 还低一档**，属于「未验证区间」。

### 4.2 llm-bench.io 社区跑分

`https://llm-bench.io/models/qwen3-8-flash-next`（截至 2026-10）：5 次提交

| 硬件 | 工具 | 量化 | 峰值 tok/s | 平均 tok/s | 上下文 | 质量分 |
|---|---|---|---:|---:|---|---:|
| TITAN RTX **24GB** 单卡 | llama.cpp | 未标 | **17.5** | 17.5 | 65,536 | 85.9 |
| 8× RTX 4090 D（384GB 合计） | vLLM | 未标 | 172.0–174.8 | 173.4 | 262,144 | 75.9–79.6 |

→ **单卡 24GB 用 llama.cpp 只有 17.5 tok/s**，说明「单卡能跑」和「跑得快」是两回事；这也是 airllm 那类逐层流式方案的上限参照。

### 4.3 结论性判断

- Flash-Next 要跑到「比现有基线（29~83 tok/s）有点意义」的速度，**已发布的最低配置是 12GB 显存 + 32~64GB 内存**（Strata Q2_0/IQ2_XS ≈ 40~48 tok/s）。
- 6GB 显存 + 32GB 内存：**没有任何已发布测量**。按 Strata 文档只能进 low-RAM/SSD 流式，属于「能出字但不知道多慢」，且 RAM 34GB 专家量 > 32GB 物理内存，必然触发大量换页。

**前三名（能在这台机器上真正落地的）**：

1. **维持现状：Ollama LFM2.5 8B-A1B（83 tok/s）+ Qwen3.6 35B-A3B（29 tok/s）** — 唯一有本机实测的「可用」组合，别再折腾。
2. **Qwen3-30B-A3B 4bit 17.3GiB（Ollama/llama.cpp）** — 若要 Qwen3 家族、要更大的总参数：体积/内存都安全，MoE 3B 激活，预期 10–18 tok/s【推算】，质量与 35B-A3B 同代偏旧；**唯一的换机动机是它比现在更省显存**，不是更强。
3. **Qwen3.8-27B 4bit 15.3GiB（Ollama 已有 `qwen3.8:27b` tag）** — 想要「Qwen3.8 代」质量：dense 27B 在 6GB 卡上必然大量 CPU 卸载，预期只有 3–6 tok/s【推算】，会明显慢于现在的 29 tok/s。

**明确排除**：airllm + Flash-Next（磁盘 360GB > 188GB、内存 64GB > 32GB、Windows 实慢到 28.6s/token）；Qwen3-Next-80B-A3B（4bit 45GiB > 32GB 内存）；airllm + 任何 ≥30B 模型的「能用速度」幻想（每次 token 全盘读一遍）。

### 5.1 GGUF 路线要点（Flash-Next）

- 想要「本地真的跑起 Flash-Next」只有 **llama.cpp + ISTA-DASLab Q2_0（61.9GiB，下载≈66.5GB）** 或 unsloth UD-IQ1_S（61.8GiB）。**注意：没有「免安装一键」路线**，Ollama 官方只有 MLX tag（Apple 专用）。
- llama.cpp 主线已支持 qwen4exp（#27739 merged）；MTP 投机解码要 fork 分支；已知 open bug：#27763、#30887、#29149。
- 更省内存的第三方外壳是 **Strata**（MIT，Windows 安装包 0.2.9）：支持 ISTA-DASLab/Unsloth/Gyro 多档，RAM 不足时可 SSD 流式——但 6GB 卡不在其文档验证范围。
- **必须承认的空白**：6GB 显存 + 32GB 内存 + 188GB 盘的 Flash-Next 实测/Q&A 在 GitHub issues、Reddit、知乎、V2EX、X 上**都没找到**。只找到 airllm 自己的 4090 数据与 Strata 的 ≥12GB 数据。

## 6. 逐项体检：这台机器 vs 各路线硬门槛

| 门槛 | 机器实际 | airllm+BF16 Flash-Next | airllm+FP8 | GGUF Q2_0 + Strata/llama.cpp | 现有 Ollama 基线 |
|---|---|---|---|---|---|
| 磁盘 | 188.6GB | 需 ~360GB+切分副本 → **✗** | 185.6GB 下载 + 切分 → **✗** | 66.5GB 下载 ✅ | ✅ |
| 内存 | 32GB DDR4 | 官方要 64GB → **✗** | 51GB+ → ✗ | 门槛 37.6GB 模型内存/44GB RAM → **✗ 边缘** | ✅ |
| 显存 | 6GB | 5.95GB 宣称 → 理论 ✅（但 Windows 长 prompt O(n²) 会炸，#396） | ✗ | Strata 文档最低 12GB → 未验证 | ✅ |
| 系统 | Win11 | 无官方支持声明；#364/#396 实测 10.9~28.6 s/token | 同左 | llama.cpp/Strata 都有 Windows 包，但 6GB 未验证 | ✅ 已实测 |

**唯一「三项全绿」的结论：不要在这台机器上跑 Flash-Next；本地继续用 Ollama 现有模型，Flash-Next 需求走云 API。**

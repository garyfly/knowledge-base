# 本地模型部署与量化（Qwen3.8 可行性评估）

> [!important] 一句话结论
> **Qwen3.8-27B 在 G15 5511 上能跑，但强度不对等**：能力比现有的 `qwen3.6:35b-a3b` 高出一代（Agent / 编码近乎翻倍），速度却只有它的 **1/2~1/3**（预估 2.5~4 tok/s）。
> 根本瓶颈是 **6GB 显存 + 31.5 GB/s 内存带宽**，不是模型本身。真正的解法是 **eGPU**（机器里有雷电控制器，待确认接口通道）。

## 二、实测速度基线

用 Ollama API 跑固定 64 token 输出测得：

| 模型 | 运行方式 | 输出速度 | 加载耗时 |
|---|---|---|---|
| `fast`（9.7B Q4） | GPU + CPU 混合 | **15.4 tok/s** | 14.7s |
| `fast`（9.7B Q4） | 纯 CPU（`num_gpu=0`） | **5.25 tok/s** | 15.8s |
| `qwen3.6:35b-a3b-coding` | 默认 | **6.7 tok/s** | 48.9s |

> [!note] 关键推算：你的内存带宽天花板
> 纯 CPU 跑 9.7B dense 时，每个 token 要读约 6.0GB 权重：
> `6.0GB × 5.25 tok/s ≈ 31.5 GB/s`
> 这个数字约等于 DDR4-2667 双通道的实测可用带宽。
> **推论：任何模型的输出速度上限 ≈ 31.5 ÷（每个 token 实际读取的 GB 数）。**

> [!warning] 为什么 35B 反而比 9B 快
> `qwen3.6:35b-a3b` 是 **MoE**，总参数 35.5B 但每个 token 只激活约 3B（读取约 2GB），所以能到 6.7 tok/s。
> 而 **dense** 模型每个 token 都要读完整份权重 —— 这就是 Qwen3.8-27B（dense）会慢的原因：**参数量更小，速度反而更差**。

## 三、Qwen3.8 家族（2026-08-14 开源，Apache 2.0）

| 型号 | 结构 | 本机能否部署 |
|---|---|---|
| Qwen3.8-2.4T-A95B（Max） | 2.4T MoE，激活 95B | ❌ 只能走 API |
| Qwen3.8-Flash-Next | 125B-A6B MoE，Q4 约 68GB | ❌ 32GB 内存装不下 |
| **Qwen3.8-27B** | **27.3B dense，唯一 dense** | ✅ **只有这一个** |

Qwen3.8-27B 要点：

- 64 层中只有 **16 层全注意力**，其余 48 层是 Gated DeltaNet 线性注意力 → KV 缓存很省，64K 上下文开销可接受
- 原生 **256K 上下文**（YaRN 可扩到约 1M）
- 自带**视觉**（VLM，mmproj 约 0.93GB）
- **默认开启思考模式**（`reasoning_effort` = xhigh / medium / low）
- 架构名仍是 `Qwen3_5ForConditionalGeneration` → **现有 Ollama / llama.cpp 直接支持，无需等更新**

> [!tip] Ollama 官方标签
> `qwen3.8` 的 12 个标签全是 27B（`27b-q4_K_M` / `27b-mtp-q4_K_M` / `27b-q8_0` / `27b-bf16` / `nvfp4` / `mxfp8` / `mlx` 等），**最小就是 18GB 的 4-bit**，没有 9B 或更小的官方尺寸。
> 想更小只能走 Unsloth GGUF 或社区蒸馏。

### 量化与内存需求（Unsloth 建议值，内存 + 显存总和）

| 量化 | 建议总内存 | 本机 32GB + 5.2GB 显存 |
|---|---|---|
| 1-bit | 7~8GB | ✅ 宽裕 |
| 2-bit | 9~11GB | ✅ |
| 3-bit（UD-IQ3_XXS 10.93GB） | 12~14GB | ✅ **推荐区间** |
| 4-bit（Q4_K_M 约 17~18GB） | 16~19GB | ⚠️ 能装，但 CPU 卸载比例高 → 很慢 |
| 6-bit | 23~26GB | ⚠️ 勉强 |
| 8-bit | 31GB | ❌ 已到极限 |
| BF16 | 56GB | ❌ |

## 四、本机速度预期：Qwen3.8-27B

用本机带宽反推（以 3-bit 10.9GB 为例，约 3.5GB 进显存、6.7GB 走 CPU）：

```
CPU 部分：6.7GB ÷ 31.5 GB/s ≈ 0.21 秒/token
叠加显存部分与开销  →  预计 2.5 ~ 4 tok/s
开启 MTP 投机解码（draft_num_predict 4）可能到 3 ~ 5 tok/s
```

> [!info] 社区实测对照（佐证推算量级）
> - RTX 3060 **12GB 桌面版**，3-bit 整份进显存 → **约 20 tok/s**（[龐果設計实测](https://www.pongo.com.tw/qwen3-8-27b-12gb-llama-cpp/)）
> - 同卡 + 32GB DDR4，4-bit 把 46 层 FFN 丢 CPU + MTP → **约 9.7 tok/s**
> - 本机只有 6GB，CPU 卸载比例远高于上面两种 → 落在 2~4 tok/s 合理

⚠️ 以上为**推算值，非本机实测**。要确认需实际下载 GGUF 跑一遍。

**结论：能力跨一代，速度降一个量级。** 适合"丢任务挂后台慢慢跑"，不适合交互式对话和 Agent 循环。

## 六、三个必须知道的坑

> [!warning] 1. 思考模式在慢硬件上极贵
> Qwen3.8 默认 `reasoning_effort=xhigh`。社区在 12GB 桌面上同一道编程题**想了 28.4 分钟、烧完 3 万 token，一行代码都没交出来**。
> 本机速度只有其 1/5 → 必须设 `reasoning_effort=low` 或直接关思考（`enable_thinking: false`）。

> [!warning] 2. 别用 Ollama 默认标签
> 官方最小标签是 18GB 的 4-bit，对 6GB 显存是最差路径。
> 应该用 llama.cpp + Unsloth `UD-IQ3_XXS`（10.93GB），或社区的 IQ3 量化 Ollama 包。

> [!warning] 3. 6GB 显存极易 OOM
> 社区在 12GB 上都要把 `-ub` 调到 256、加 `--no-mmproj-offload` 才不崩。本机更紧张，建议干脆不加载视觉模块。

## 七、升级路线（按性价比）

| 方案 | 成本 | 效果 | 评价 |
|---|---|---|---|
| 内存 32→64GB DDR4-3200 | 几百元 | 带宽仅 +20%，能装更大量化/更长上下文 | ⚠️ 不解决根本瓶颈 |
| **eGPU（雷电外接 16~24GB 显卡）** | 中高 | 27B Q4 整份进显存 → 参考 12GB 桌面卡的 20 tok/s | ✅ **质变，优先验证可行性** |
| 换统一内存主机（Mac Studio / Ryzen AI Max 类） | 高 | 可跑 125B 级 MoE | ✅ 长期方案 |
| 换桌面独显主机 | 高 | 24GB+ 显存，最省心 | ✅ |

> [!question] eGPU 待确认
> 本机检测到 `Thunderbolt(TM) Controller - 9A1F`（Tiger Lake-H 内置 TB4 控制器，状态 OK），但 **OEM 可能未把该控制器接到 Type-C 口**。
> 需要向 Dell 确认 G15 5511 的 Type-C 是否走雷电通道，或买支持退货的扩展坞实测。

## 九、附：本次测量用的命令

```powershell
# 硬件信息
Get-CimInstance Win32_Processor | Select-Object Name, NumberOfCores, NumberOfLogicalProcessors
Get-CimInstance Win32_VideoController | Select-Object Name, AdapterRAM
nvidia-smi --query-gpu=name,memory.total,memory.used,memory.free --format=csv

# 现有模型清单
ollama list
ollama show <model> --modelfile

# 测速（改 num_gpu=0 可测纯 CPU）
$body = @{ model="fast"; prompt="用一句话解释什么是量化。"; stream=$false;
           options=@{ num_predict=64; temperature=0.2 } } | ConvertTo-Json -Depth 4
$r = Invoke-RestMethod -Uri 'http://127.0.0.1:11434/api/generate' -Method Post `
      -Body $body -ContentType 'application/json' -TimeoutSec 900
$r.eval_count / ($r.eval_duration / 1e9)   # tokens/s
```

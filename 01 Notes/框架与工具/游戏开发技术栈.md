# 游戏开发技术栈

> [!important] 一句话结论
> 做游戏的「技术栈」不是一条链，而是按 **平台 / 品类 / 团队规模** 分成几套差异很大的组合。
> 快速对应：**3A 主机 PC → UE5 + C++**；**商业手游 → Unity + C# + Lua 热更 + skynet**；**小游戏 → Cocos Creator + TypeScript**；**独立游戏 → Godot 4 / Unity**。

## 一、引擎（最核心的选型）

| 引擎 | 语言 | 主战场 | 典型作品 |
| --- | --- | --- | --- |
| **Unreal Engine 5** | C++ / Blueprint | 3A 主机 PC、高品质手游 | 黑神话悟空、Fortnite |
| **Unity** | C# | 手游、独立、VR/AR、跨平台 | 原神（魔改）、Among Us、空洞骑士 |
| **Cocos Creator** | TypeScript | 微信/抖音小游戏、H5、休闲手游 | 国内小游戏生态主力 |
| **Godot 4** | GDScript / C# | 独立游戏、2D、小团队 | Brotato 等独立爆款 |
| **自研引擎** | C++ | 顶级大厂 | 育碧 Anvil / Snowdrop、EA Frostbite、R星 RAGE |
| **LayaAir / Egret** | TS / JS | H5、小游戏（Egret 已边缘化） | — |
| **GameMaker / RPG Maker / Love2D / MonoGame / Bevy(Rust)** | GML / Ruby / Lua / C# / Rust | 小众、原型、2D 独立 | — |

Web 端另有一条线：**Three.js / Babylon.js / PlayCanvas + Phaser / PixiJS**。

## 二、编程语言的分工

- **C++**：UE、自研引擎、性能敏感的服务端
- **C#**：Unity 主力，Godot 可选
- **Lua**：国内手游**热更新刚需**（xLua / ToLua / slua + 服务端 skynet）
- **TypeScript / JS**：Cocos、H5、小游戏
- **Python**：工具链、TA 脚本、打包流水线、部分服务端
- **Go**：现代游戏服务端（高并发网关、匹配、战斗服）
- **Java**：存量手游服务端、渠道 SDK
- **Rust**：新兴服务端、Bevy 引擎、性能模块

## 三、服务端与网络

- **框架**：skynet（Lua，国内手游最普遍）、Pomelo（Node.js，网易系）、KBEngine、自研；商业方案 **Photon**、**Nakama**、**PlayFab**
- **部署**：K8s + **Agones**（专用游戏服编排）、AWS GameLift
- **协议**：TCP + Protobuf / FlatBuffers 自定义二进制、**KCP / QUIC** 加速、WebSocket（H5）、gRPC（内部微服务）
- **存储**：MySQL（角色数据）+ Redis（缓存/排行榜）、MongoDB、Kafka（日志/事件）

## 四、内容生产与中间件

- **DCC**：Maya / Blender / 3ds Max、ZBrush、Substance Painter & Designer、Houdini、Marvelous Designer
- **音频**：**Wwise**、**FMOD**（大项目标配）、CRIWARE
- **物理**：PhysX、Havok、Jolt、Box2D
- **2D 动画**：Spine、DragonBones、Live2D
- **同步 / 联机**：Unity 的 Netcode for GameObjects / Mirror / FishNet；UE 自带 Replication + GAS；商业 Photon
- **反作弊**：EAC、BattlEye、腾讯 ACE
- **Shader**：HLSL / GLSL / 引擎节点材质

## 五、工程化（容易忽略但很关键）

- **版本控制**：大团队几乎都用 **Perforce**（美术二进制资源），小团队 Git + **LFS**
- **CI/CD**：Jenkins / GitLab CI / TeamCity，负责每日构建、多平台出包
- **热更新**：Lua 脚本热更、AssetBundle / Addressables、**HybridCLR / ILRuntime**（C# 热更）
- **项目管理**：Jira + Confluence / TAPD

## 六、按场景的「成套配置」

| 场景 | 典型技术栈 |
| --- | --- |
| 手游 MMO / 卡牌 | Unity + C# + Lua 热更 + skynet 服务端 + MySQL/Redis |
| 微信 / 抖音小游戏 | Cocos Creator + TypeScript + 云开发或自研 Node/Go |
| 3A 单机 | UE5 + C++ + Wwise + Houdini + Perforce |
| 休闲 / 超休闲 | Unity 或 Cocos + AppLovin / ironSource 广告 SDK + 快速 A/B |
| 独立游戏 | Godot 4 / Unity / GameMaker |
| 重度联机 | C++ / Go 自研帧同步或状态同步 + K8s + Agones |
| VR / AR | Unity + XR Interaction Toolkit，或 UE |

## 七、中国市场的两个显著特征

1. **热更新属刚需**（版号与运营节奏），所以 Lua 生态异常发达。
2. **小游戏生态独立成体系**：Cocos + TypeScript 几乎是默认答案。

## 八、趋势（2025 → 2026）

- UE5 的 **Nanite / Lumen** 拉高画质门槛，同时抬高美术与优化成本。
- Unity 6 统一 URP / HDRP，移动端管线收敛。
- **Godot 4** 在小团队中份额明显上升。
- 服务端向 **Go / Rust + 云原生** 演进。
- **AIGC** 开始进入美术与程序管线：资产生成、代码补全、配音。
- 云游戏、WebGPU 在观望期。

## 九、个人开发者的落地方案

上面讲的是"行业里有什么"。如果你要**一个人、每周 10~15 小时、把游戏卖到 Steam**，选型与路线完全不同：

→ 见 [[02 Projects/独立游戏开发到 Steam 上线/README|独立游戏开发到 Steam 上线]]（技术栈定选、24 周排期、范围与功能裁剪决策卡、Steam 上架与营销全流程）
